# 标书中心 V1 验收基准

- 日期：2026-09-04
- 状态：Industry Baseline R1，待第 0 步确认
- 行业依据：`industry-baseline-v1.md`
- 合成夹具：`fixtures/synthetic-bid-v1.json`
- 重要说明：合成数据只用于测试结构、权限和输出，不代表任何真实工程或商务承诺

## 1. 黄金场景

`BID-TEST-001` 代表一个虚构的出口工业设备项目，用于覆盖：

- 英文、中文和双语输出。
- 技术模板、商务模板和公共资料快照。
- 技术参数、设备清单、范围矩阵和长表格。
- 价格、付款、交货、质保和商务偏差。
- 项目章节修改、项目新增、明确省略和恢复标准内容。
- 技术章节协作和商务数据权限。
- 技术、商务和完整标书审批。
- `QP-V1` 发布以及从 V1 创建 V2。
- 六类 DOCX/PDF、附件 ZIP 和 manifest。

## 2. 黄金流程

1. 从合成商机 `OPP-TEST-0001` 创建主标书工作区。
2. 选择一个发布的双语技术模板和一个发布的双语商务模板。
3. 冻结模板、条款、公共资料和输出样式修订。
4. 从合成 CRM 数据预填项目和客户字段。
5. 人工填写缺失工程和商务变量。
6. 修改一个技术章节、一个商务章节，并新增一个项目附件。
7. 将一个技术章节分派给 Supporting Engineer。
8. 运行完整性检查并处理所有缺失项。
9. Project Lead 提交技术包，Technical Manager 批准为 `TS-V1`。
10. 商务负责人提交商务包，Commercial Manager 批准为 `CP-V1`。
11. 装配完整标书并批准为 `QP-V1`。
12. 生成和下载所有文件，核对 manifest 和 SHA-256。
13. 从已发送 V1 创建 V2，修改交货期和客户可读摘要。
14. 验证 V1 不变，V2 差异准确。

## 3. 内容验收

- 技术包包含冻结规范第 6.1 节要求的适用章节。
- 商务包包含冻结规范第 6.2 节要求的适用章节。
- `omitted` 可选章节不进入目录或正文。
- 项目新增章节显示为 `project_added`。
- 修改章节显示为 `customized`，并可查看标准快照与当前内容。
- 恢复操作只恢复当前项目章节，不改变模板或其他项目。
- 所有引用条款和公共资料显示稳定代码与修订号。
- 不存在 `{{variable}}`、空标题、未解析字段或内部测试备注。

## 4. 数据一致性验收

- 技术包、商务包和完整标书的客户、项目、商机和版本一致。
- 供货范围与报价包含项可对照且无未确认冲突。
- 技术交付计划与商务交货承诺无未确认冲突。
- 技术质保内容与商务质保期限无未确认冲突。
- 报价总额等于分项合计，币种和税费明确。
- 所有正式变量保留来源、值、覆盖人和覆盖时间。

## 5. 权限验收

- 无商机可见权限的用户无法访问工作区、页面、API 或文件。
- Supporting Engineer 只能编辑分派的技术章节。
- 仅技术协作用户不能读取价格、付款和合同商务内容。
- Salesperson 不能发布技术或商务模板。
- Technical Manager 不能批准商务包。
- Commercial Manager 不能批准技术包。
- Administrator 不能替代正常技术或商务业务审批。
- 只有授权人员能发送批准的完整标书。

## 6. 版本和不可变性验收

- 发布模板不能原地修改或删除。
- 项目创建后，模板新修订不改变项目快照。
- 批准的 `TS-V1` 和 `CP-V1` 不可修改。
- `QP-V1` 发送后不可修改、覆盖或删除。
- 创建 `QP-V2` 必须从当前发送版本克隆并填写两种修订说明。
- V2 发布只把 V1 标记为 superseded，不删除 V1 文件或历史。
- 数据库直接更新不可变内容时被拒绝。

## 7. 输出文件验收

预期包：

```text
OPP-TEST-0001_Technical-Package_Bilingual_TS-V1.docx
OPP-TEST-0001_Technical-Package_Bilingual_TS-V1.pdf
OPP-TEST-0001_Commercial-Package_Bilingual_CP-V1.docx
OPP-TEST-0001_Commercial-Package_Bilingual_CP-V1.pdf
OPP-TEST-0001_Complete-Bid_Bilingual_QP-V1.docx
OPP-TEST-0001_Complete-Bid_Bilingual_QP-V1.pdf
OPP-TEST-0001_Attachments_QP-V1.zip
OPP-TEST-0001_Manifest_QP-V1.json
```

每个文件必须：

- 存在数据库记录和 SHA-256。
- 绑定准确的技术、商务和报价包版本。
- 只能通过授权下载路由获取。
- 文件名、MIME、大小和 manifest 一致。
- 生成失败时不得保存部分正式文件。

## 8. DOCX/PDF 视觉验收

- 封面、目录、正文、附录顺序正确。
- Logo 清晰且无变形。
- 中文、英文、上下标、单位和符号无乱码。
- 目录页码正确。
- 标题不孤立在页底。
- 表头跨页重复，单元格没有覆盖或截断。
- 宽表按规则使用横向页或可读列宽。
- 图片和图纸预览保持比例。
- 页眉页脚、文件号和版本号贯穿一致。
- DOCX 和 PDF 的正文、表格和附件索引一致。
- 无意外空白页、缺页和重复页。

## 9. 浏览器验收

- 桌面宽度下章节目录、编辑区和来源/差异区可用。
- 移动宽度下不出现不可访问的操作或横向遮挡。
- 中英文导航完整，中文长标题不异常逐字换行。
- 自动保存后刷新页面数据不丢失。
- 提交、退回、批准和版本创建显示明确结果。
- 直接访问无权限路由返回 403 或安全重定向。

## 10. 性能候选门槛

在合成夹具和普通开发机环境下：

- 项目标书工作区初次加载目标小于 3 秒。
- 普通章节保存目标小于 1 秒，不含网络环境波动。
- 完整标书生成应显示进度，不阻塞 Web 服务健康检查。
- 100 页以内完整 PDF 的候选生成目标小于 60 秒。
- 超时或失败应产生可重试的失败记录，不产生已批准文件。

性能门槛作为 V1 初始服务目标；本地实现后通过真实 DOCX/PDF 渲染数据校准，调整必须形成有证据的新修订。

## 11. 企业校准项

- 如有历史标书，校准章节顺序、企业措辞和常见附件，但不直接视为可复用内容。
- 企业未提供正式样式时，使用 `output-style-v1.md` 的行业基线 R1。
- 双语默认同一章节内中文在前、英文在后；不采用跨页双栏。
- 正式矢量 Logo 到位前，现有 Logo 只用于本地生成与视觉测试。
- 资质、业绩、证书和合同条款必须逐项审核、设置适用范围与有效期后才能发布到内容库。
- 客户招标文件的格式、内容和提交要求始终高于本基线，并通过合规矩阵追踪。

以上校准项不阻塞第 1 步。行业来源、明确默认规则和合成夹具已形成可重复的第 0 步验收基准，等待用户确认。
