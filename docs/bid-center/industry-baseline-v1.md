# BESTCRM 标书中心 V1 行业实践基线

- 日期：2026-09-04
- 状态：Baseline R1，待第 0 步确认
- 适用范围：工业设备项目的 RFI、RFQ、RFP、技术协议、商务报价和完整标书
- 设计原则：行业基线先行，企业历史样本用于后续校准，不作为第 1 步启动条件

## 1. 权威依据

本基线采用以下公开的正式来源，不宣称 BESTCRM 已取得相应认证：

1. [APMP Winning Business Ecosystem](https://www.apmp.org/Web/Web/About-Us/Winning-Business-Ecosystem.aspx)：采用需求审查、合规矩阵、职责与里程碑、分阶段评审、最终质量检查、提交确认和复盘归档。
2. [APMP Body of Knowledge - Bid & Proposal Writing v4](https://www.apmp.org/assets/BoK-BW-M.v4.pdf)：采用内容计划评审、接近完成时的独立全文评审，以及编辑后的校对和格式一致性检查。
3. [ISO 9001:2015 documented information guidance](https://www.iso.org/files/live/sites/isoorg/files/standards/docs/en/iso_9001_2015_guidance_documented_information.pdf)：采用受控文件、客观证据、设计输入/输出/变更记录、授权发布和可追溯责任人。
4. [ISO 15489-1:2016](https://www.iso.org/standard/62542.html)：采用记录创建、捕获、元数据、责任、控制和长期管理原则。ISO 页面显示该版本仍为现行版本。
5. [NIST Role-Based Access Control](https://csrc.nist.gov/projects/role-based-access-control)：采用用户、角色、权限、操作和对象的 RBAC 模型，并通过约束实现职责分离。
6. [ISO 19005-2:2011](https://www.iso.org/standard/50655.html)：将 PDF/A-2 作为需要长期保存时的可选输出配置；V1 默认 PDF 不强制宣称 PDF/A 合规。

引用核对日期为 2026-09-04。后续如标准版本变化，形成新的基线修订，不原地覆盖 R1。

## 2. 适用优先级

每个项目按以下优先级确定内容与格式：

1. 客户招标文件、澄清文件和正式补遗。
2. 项目适用的法律、法规、强制标准和合同要求。
3. 公司已批准政策、条款、模板、授权和品牌规则。
4. 本行业实践基线。
5. 项目团队建议。

高优先级要求覆盖低优先级默认值时，必须记录来源、差异、责任人和批准结果。系统提供合规与追溯能力，但不自动判定某项法律或工程标准是否适用。

## 3. 标准工作流

| 阶段 | 必做动作 | 受控产物 | 进入下一阶段的条件 |
|---|---|---|---|
| 0. 机会与投标决策 | 识别客户、范围、时间、资格、风险和负责人 | Bid/No-Bid 记录、初始风险 | 决策及责任人明确 |
| 1. 要求审查 | 拆解 RFI/RFQ/RFP、图纸、数据表、澄清和补遗 | 来源文件、要求项、合规矩阵 | 每项要求有编号、来源和责任人 |
| 2. 标书策划 | 确定赢单主题、解决方案、目录、日程和 RACI | 标书计划、内容计划、评审计划 | 技术、商务、评审和发布责任已分配 |
| 3. 内容编制 | 从已发布模板和受控内容库创建项目快照，再做项目化修改 | 技术草稿、商务草稿、偏差和附件 | 必填输入完整，修改可追溯 |
| 4. 专业评审 | 技术、商务、价格、合同和合规分别评审 | 评审意见、处置记录、审批快照 | 重大意见关闭或获得有权人接受 |
| 5. 综合评审 | 由未主笔全文的人员模拟客户检查完整性、响应性和一致性 | 综合评审记录、最终整改清单 | 合规矩阵闭环，跨包冲突为零 |
| 6. 发布与提交 | 校对、版式检查、批准、生成、哈希和清单 | TS-Vn、CP-Vn、QP-Vn、ZIP、manifest | 仅批准版本可发送，提交方式符合客户要求 |
| 7. 提交后管理 | 记录提交和回执，管理澄清、修订、结果和复盘 | 提交记录、澄清记录、下一版本、经验教训 | 记录归档，优质内容经审核后回收到内容库 |

V1 产品代码覆盖阶段 1 至阶段 7 中的标书编制、评审、发布和记录能力；自动 Bid/No-Bid 评分、自动解析客户招标文件和投标平台直连不在 V1 范围。

## 4. 合规矩阵

每个客户要求形成一条可追踪记录，最低字段为：

- 要求编号、来源文件、来源修订、页码或章节、客户原文。
- 类型：技术、商务、法律、提交、资质、格式或附件。
- 强制性、评分权重、截止时间和责任人。
- 响应状态：`unassigned`、`drafted`、`compliant`、`deviation`、`not_applicable`、`needs_clarification`。
- 响应章节、证据文件、偏差说明、批准人和关闭时间。

完整标书发布前，所有强制要求必须为 `compliant`、已批准的 `deviation` 或有依据的 `not_applicable`。`needs_clarification` 不得静默关闭。

## 5. 评审门

| Gate | 评审重点 | 默认负责人 | 系统结果 |
|---|---|---|---|
| G0 要求基线 | 是否完整拆解客户要求和补遗 | Quotation Engineer / Salesperson | 合规矩阵基线 |
| G1 内容计划 | 目录、策略、证据、责任和里程碑是否可执行 | Quotation Engineer | 已批准内容计划 |
| G2 技术评审 | 工况、参数、范围、接口、偏差、保证和验收 | Technical Manager | `TS-Vn` 或退回 |
| G3 商务评审 | 价格、税费、付款、交货、贸易、质保和合同偏差 | Commercial Manager | `CP-Vn` 或退回 |
| G4 综合评审 | 响应性、可读性、跨包一致性和客户视角 | 非主笔评审人 | 整改清单及关闭记录 |
| G5 发布检查 | 校对、目录、页码、附件、文件名、哈希和提交指令 | Quotation Engineer | 发布候选 |
| G6 最终批准 | 授权、承诺和发送范围 | 配置的最终审批人 | `QP-Vn` |

G2 与 G3 独立；技术批准不能替代商务批准。涉及价格、付款、合同或重大偏差时，编制人与批准人应分离。小团队确需同一人处理时，必须使用显式例外授权和额外最终审批，不允许系统静默自批。

## 6. 受控内容生命周期

模板、条款、资质、业绩和公司资料统一使用：

```text
draft -> in_review -> published -> retired
```

最低控制规则：

- 只有 `published` 修订可用于新项目。
- 项目创建时复制准确修订快照，不持续引用最新版。
- `published` 和项目已批准快照不可原地修改。
- 内容必须记录稳定代码、修订、语言、适用范围、责任人、来源、敏感级别、生效日期和复审日期。
- 证书、授权、业绩和其他时效性内容必须记录到期日；过期或待复审内容阻止正式发布。
- 项目改写只保留在项目内；回收到内容库必须形成新草稿并重新评审。

## 7. 版本与记录

- 草稿可持续编辑，但每次提交评审都形成不可变快照。
- 技术、商务和完整标书分别编号，批准对象不能混用。
- 已发送版本只允许 `sent`、`superseded`、`accepted` 等状态变化，不允许覆盖文件。
- 每个输出保存对象版本、生成器版本、输出样式修订、文件大小和 SHA-256。
- 提交记录保存发送人、批准依据、接收方、渠道、时间、文件集合和客户回执。
- 新版本必须记录内部修订原因和客户可读变更摘要。

## 8. 权限与职责分离

权限同时受角色、商机可见范围、章节分派和对象状态约束：

- Salesperson：维护客户要求、澄清和提交信息，不批准技术或商务内容。
- Supporting Engineer：仅编辑获分派的技术章节，不能读取受限商务数据。
- Project Lead Engineer：整合并提交技术包，不能批准自己的技术提交。
- Technical Manager：技术批准，不批准商务包。
- Commercial Manager：商务与价格批准，不批准技术包。
- Quotation Engineer：装配、合规检查和输出，不替代专业批准。
- Administrator：管理系统与元数据，不默认拥有业务审批权。

所有页面、API、下载、生成和发送动作均执行服务器端授权；前端隐藏菜单不视为权限控制。

## 9. 输出行业基线

- 正式输出包含独立技术包、独立商务包、合并完整标书、附件 ZIP 和 manifest。
- 默认 A4 纵向；大表和图纸索引可使用横向节。
- 封面不显示页眉页脚；目录及正文使用自动页码和自动目录。
- 双语默认同一章节内中文在前、英文在后；长正文不使用跨页双栏。
- 草稿显示 `DRAFT / 草稿`；批准发布版不带草稿水印。
- 正式版显示文件编号、版本、发布日期和保密级别。
- DOCX 用于授权编辑和交付，PDF 用于固定版式；需要长期保存时可配置 PDF/A-2 输出和验证，不在未验证时标注合规。
- 二维码、电子签章和投标平台自动提交不在 V1 范围，只预留签署位置。

## 10. 第 0 步结论

行业来源、工作流、内容分类、输出样式、合成夹具和验收规则已经足以形成可重复的 V1 设计基线。企业历史标书、正式品牌文件和公共资料继续作为校准与内容入库材料；缺失时使用安全默认值和占位结构，不编造客户、工程、价格、业绩、证书或合同承诺。

本基线经第 0 步确认后进入第 1 步。客户特定要求和企业新规则通过新修订或设计变更记录吸收，不回写覆盖 R1。
