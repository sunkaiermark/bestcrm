# 标书中心 V1 输出样式行业基线 R1

- 日期：2026-09-04
- 状态：Industry Baseline R1，待第 0 步确认
- 目的：为 DOCX/PDF 生成和逐页视觉验收提供统一基准

## 1. 当前资产结论

- 临时使用 `src/public/assets/sunkaier-logo.png` 做原型和测试。
- 正式输出前应提供矢量 Logo 或满足印刷分辨率的透明背景高分辨率文件。
- 基线品牌色来自当前 BESTCRM 视觉基础：深蓝 `#0B1F3A`、品牌蓝 `#1E5AA8`、橙色 `#F05A24`。
- 正式字体必须在新加坡服务器具有可嵌入或可稳定渲染的中英文字体文件。

## 2. 页面

| 项目 | 基线规则 |
|---|---|
| 纸张 | A4；技术大表或图纸索引允许单独横向页 |
| 默认方向 | 纵向 |
| 页边距 | 上 18 mm、下 18 mm、左 20 mm、右 18 mm |
| 装订 | 左侧装订，不把正文放入装订安全区 |
| 封面 | 无页眉页脚；不显示目录页码 |
| 正文页码 | 封面不编号；从目录第一页开始使用连续阿拉伯数字 |
| 背景 | 白色；不使用影响打印的整页深色背景 |

## 3. 字体和层级

基线字体：

- 中文：优先使用经许可并可在服务器嵌入的 Noto Sans CJK SC 或公司指定字体。
- 英文：Arial 或与公司正式模板一致的字体。
- 代码、文件哈希和技术编号：等宽字体，仅用于内部记录或 manifest。

基线字号：

| 元素 | 字号 | 样式 |
|---|---:|---|
| 封面项目名称 | 24–28 pt | 深蓝、加粗、居中 |
| 封面文件类型 | 18–22 pt | 技术包/商务包/完整标书 |
| 一级标题 | 16 pt | 编号、深蓝、段前分页可配置 |
| 二级标题 | 13 pt | 加粗 |
| 三级标题 | 11 pt | 加粗 |
| 正文 | 10.5 pt | 1.35–1.5 倍行距 |
| 表格 | 8.5–9.5 pt | 表头加粗、重复表头 |
| 页眉页脚 | 8–9 pt | 灰色或深蓝 |

## 4. 封面字段

技术包、商务包和完整标书统一包含：

- SUNKAIER Logo。
- 客户名称。
- 项目名称。
- 文件类型。
- 商机编号或报价编号。
- 文件编号。
- 正式版本号。
- 输出语言。
- 发布日期。
- 保密级别。
- 编制、审核和批准信息。

封面不得显示内部成本、草稿备注或内部修改原因。

## 5. 页眉页脚

页眉基线内容：

- 左侧：SUNKAIER Logo 或公司名称。
- 中间：项目名称或缩写。
- 右侧：文件编号和版本号。

页脚基线内容：

- 左侧：保密级别。
- 中间：公司名称。
- 右侧：`第 X 页 / 共 Y 页` 或 `Page X of Y`。

技术包、商务包和完整标书使用相同品牌框架，但文件类型和版本必须清晰可辨。

## 6. 目录和章节编号

- 目录由生成器基于实际输出章节生成，不接受手工页码文本。
- 一级章节使用 `1`、`2`、`3`。
- 二级章节使用 `1.1`、`1.2`。
- 三级章节最多到 `1.1.1`；更深层级使用项目符号。
- `omitted` 章节不进入目录。
- 附件使用独立附录编号，例如 `Appendix A`、`附录 A`。
- 中英文双语标题使用同一章节编号，不生成两套冲突编号。

## 7. 表格

- 表头使用浅灰或浅蓝底色，保证黑白打印仍可识别。
- 表格跨页时重复表头。
- 行不得无理由拆开；过长文本行允许跨页。
- 数值、单位和币种分别使用明确列，不把单位写入无法计算的数值字段。
- 金额保留规则、千分位和币种必须统一。
- 技术参数的数值、单位、设计值、客户要求和偏差可独立比较。
- 宽表优先调整列宽或使用横向页，不缩小到不可读。

## 8. 图片、图纸和附件

- 正文图片保留纵横比，禁止拉伸。
- 图片下方包含编号、标题和来源版本。
- PFD、P&ID 和大尺寸图纸默认作为受控附件或单独横向页面。
- PDF 输出只嵌入适合页面阅读的预览；原始 CAD 文件进入附件 ZIP。
- 证书和扫描文件进入附件时保留原文件哈希。
- 附件索引显示编号、文件名、修订、页数或大小和 SHA-256 摘要。

## 9. 双语布局

基线规则：

- 双语章节标题：中文在前、英文在后，使用同一编号。
- 短字段：中文和英文可上下排列。
- 长正文：按章节连续排列，不使用难以跨页的双栏布局。
- 参数表：短标签在同一单元格中上下排列，数值与单位保持单一数据来源。
- 客户原文不自动翻译；缺少译文时显示待确认状态并阻止正式双语输出。

## 10. 文件命名

禁止使用客户名称作为唯一文件身份。基线命名：

```text
{OpportunityNo}_{PackageType}_{Language}_{Version}_{YYYYMMDD}.docx
{OpportunityNo}_{PackageType}_{Language}_{Version}_{YYYYMMDD}.pdf
{OpportunityNo}_Attachments_{Version}_{YYYYMMDD}.zip
{OpportunityNo}_Manifest_{Version}_{YYYYMMDD}.json
```

`PackageType` 使用：

- `Technical-Package`
- `Commercial-Package`
- `Complete-Bid`

示例只使用合成项目：

```text
OPP-TEST-0001_Complete-Bid_Bilingual_QP-V1_20260904.pdf
```

## 11. manifest 最低字段

- 机会编号、客户显示名、项目名称和完整标书版本。
- 技术版本、商务版本、输出样式修订和生成器版本。
- 每个输出文件的类别、文件名、MIME、大小和 SHA-256。
- 每个附件的来源对象、修订、文件名、大小和 SHA-256。
- 生成、审核、批准和发送的用户及时间。
- 内部修订原因与客户可读变更摘要分别保存。

## 12. 视觉验收门禁

正式样式冻结前必须使用实际渲染页面检查：

- 封面没有低分辨率 Logo、拉伸或文字遮挡。
- 目录页码与正文一致。
- 标题不单独留在页面底部。
- 表格无列截断、文字覆盖或不可读缩放。
- 中文、英文、数字和符号无缺字或乱码。
- 图片清晰并保持比例。
- 页眉页脚、版本号和页码一致。
- 无意外空白页、重复页或缺页。
- DOCX 与 PDF 关键分页和内容一致。
- 黑白打印仍能区分标题、表头和状态。

## 13. 企业校准与扩展

以下内容可在企业资料到位后形成 R2 样式修订，不阻塞第 1 步：

1. A4、页边距和装订要求。
2. 正式 Logo、品牌色和字体。
3. 封面字段和签字盖章位置。
4. 页码从目录还是正文开始。
5. 中英文双语排列。
6. 技术大表和图纸的横向页规则。
7. 金额、日期、单位和编号格式。
8. 二维码或电子签章扩展；V1 只预留签署位置，不实现电子签章。

草稿统一显示 `DRAFT / 草稿` 水印；批准发布版不显示草稿水印。未完成 PDF/A 验证时，不得标注 PDF/A 合规。
