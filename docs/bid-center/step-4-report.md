# BESTCRM 标书中心 V1 第 4 步实施报告

- 日期：2026-09-04
- 状态：完成，等待用户确认
- 分支：`codex/bid-center-v1`
- 生产影响：无

## 完成范围

- 新增项目标书列表、创建向导、CRM 预填核对和主工作区详情页。
- 在机会详情新增“创建 / 打开项目标书”入口；已存在工作区时自动进入同一主工作区。
- 创建时选择当前已发布且语言兼容的技术模板、商务模板和输出样式。
- 一个数据库事务内创建主工作区、技术项目草稿 `TS-Dn` 和商务项目草稿 `CP-Dn`；任何一项失败均全部回滚。
- 主工作区冻结机会信息、技术模板修订、商务模板修订、输出样式完整设置、技术条款、商务条款/公共资料修订及附件 SHA-256。
- 商务项目草稿冻结模板内容、变量定义、校验规则、渲染内容和受控资料完整快照。
- 复用现有技术草稿生成逻辑，并为技术变量补充逐项来源记录和人工覆盖记录。
- CRM 预填覆盖客户、联系人、机会、负责人、已批准报价和交付信息；所有来源均来自显式白名单。
- 预览页允许逐项修改技术和商务变量，修改值记录为 `manual_override`，同时保留原值、来源字段及创建时值。

## 权限和安全

- 工作区创建权限定为管理员，或直接负责该机会的销售经理、项目负责人、技术经理、商务经理。
- Supporting Engineer 可按原机会规则查看已有工作区，但不能创建主工作区。
- 列表和详情仓储查询均在 SQL 层应用机会可见性：负责人、指定经理、有效团队成员和合同审批人。
- 未授权直接访问工作区或其附件不会泄露工作区是否存在。
- 受控附件下载再次执行内容分类、拥有者和敏感级权限校验，并在发送前复算 SHA-256。
- 商务权限不足时，详情页隐藏商务模板及商务草稿内容。
- `BID_CENTER_ENABLED` 继续默认关闭；关闭时仓储访问前即返回 404。
- 登录保护仅挂载到项目标书两个路由族，不影响后续邮件中心等独立模块。

## 数据一致性

- 数据库唯一约束和机会级 advisory lock 共同保证一个机会只有一个主工作区。
- 创建仅接受主表当前指向的已发布、有效且语言兼容的模板/输出样式。
- 商务模板引用的条款和公共资料必须仍是当前已发布版本，且处于有效期内。
- 商务变量执行必填、数据类型、整数、日期、最小值、最大值和允许值校验。
- PostgreSQL 触发器阻止修改工作区来源快照和商务草稿来源快照。
- 来源库后续发布新修订后，既有工作区仍引用并显示创建时冻结的旧修订和附件哈希。
- 事务内查询按顺序执行，兼容单个 `pg.Client`，没有并发查询弃用警告。
