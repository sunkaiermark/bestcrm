# BESTCRM 标书中心 V1 第 5 步实施报告

- 日期：2026-09-04
- 状态：完成，等待用户确认
- 分支：`codex/bid-center-v1`
- 生产影响：无

## 完成范围

- 新增技术包、商务包统一的项目编辑器，并从主工作区进入冻结的 `TS-Dn` / `CP-Dn` 项目副本。
- 桌面端采用三栏工作台：左侧章节树，中间项目正文，右侧标准来源、差异、变量来源、复核意见、资料建议和审计轨迹。
- 技术包和商务包均支持中英文正文、结构化表格、章节状态、负责人、章节新增、上下排序、跳过和单章节恢复标准。
- 技术包支持按章节选用冻结的标准条款；商务包支持按章节选用冻结的公共资料。
- 技术/商务变量均在项目草稿内修改，保留创建时的来源信息，并对商务变量继续执行类型和约束校验。
- 新增项目图片/附件上传、受控下载和一次性软删除；元数据和 SHA-256 保持不可变。
- “建议纳入资料库”只生成独立待评审建议，不直接修改或发布技术模板、商务模板、标准条款或公共资料。
- 每次内容变更要求填写原因，并同时写入章节变更记录和操作者审计事件。

## 权限和安全

- 技术包继续按机会责任链授权：项目负责人可编辑全部技术章节；Supporting Engineer 只能编辑分配给自己的章节。
- 商务包只向有商务可见权的成员开放；技术专属角色直接访问商务编辑器不会取得商务内容。
- 指定 Commercial Manager 可编辑全部商务章节；负责该机会的 Salesperson 只能编辑安全的客户/商务章节，价格、付款和合同章节保持只读。
- Administrator 在第 5 步只检查内容，不代替技术或商务责任人修改受控业务内容。
- 所有 GET/POST、附件下载和分配操作都在服务层重新执行权限判断，界面隐藏不是唯一保护。
- 工作区读取继续继承 SQL 层机会可见性，不绕过 `visibleToUserId` 范围。
- `BID_CENTER_ENABLED` 继续默认关闭；关闭时编辑器和写入路由在仓储访问前返回 404。

## 数据一致性

- 项目编辑仅更新工作区内的技术/商务项目草稿，不修改创建时冻结的模板修订和内容来源快照。
- 恢复操作仅恢复当前一个章节；项目新增章节可单独删除，不影响其他章节。
- 技术条款选择按章节保存，不会错误地同步到整份技术包。
- 商务公共资料在选用时深复制已发布修订内容，之后资料库发布新修订不会反向改变当前项目。
- 章节内容保存、变更记录、操作者事件和工作区更新时间处于同一数据库事务。
- 审计事件由数据库触发器强制只增不改，并校验事件中的草稿确实属于指定工作区及包类型。
- 附件元数据不可覆盖，只允许记录一次明确的移除人、移除时间和原因。
- 商务包标准基线取自冻结模板的渲染内容；未修改内容不再被误报为项目差异。
