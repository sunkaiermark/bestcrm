# BESTCRM 标书中心 V1 第 7 步实施报告

- 日期：2026-09-05
- 状态：完成，等待用户确认
- 分支：`codex/bid-center-v1`
- 生产影响：无

## 完成范围

- 基于已批准并冻结的 `TS-V`、`CP-V` 和 `QP-V` 生成一套不可变的八件套输出：技术包 DOCX/PDF、商务包 DOCX/PDF、完整标书 DOCX/PDF、附件 ZIP 和 JSON 清单。
- 技术包输出只装配技术稿和技术附件；商务包输出只装配商务稿、报价行及其受控资料；完整标书按技术包、商务包、附件索引和审批记录顺序组装。
- 文件名固定为 `{OpportunityNo}_{PackageType}_{Language}_{Version}_{YYYYMMDD}.ext`，附件包和清单在同一完整标书文件名前缀后追加用途后缀。
- 封面统一显示 Logo、客户、项目、文件类型、商机编号、正式版本、语言、发布日期、保密级别以及编制、审核、批准和生成人信息。
- DOCX 使用生成式目录域并设置打开时更新目录；PDF 在生成时写入实际目录页码。封面不编号，目录开始连续显示 `Page X of Y`。
- 页面采用 A4、18/18/20/18 mm 上下左右页边距和冻结的深蓝、蓝、橙品牌色；中英文、表格、图片、附件索引和审批记录使用统一样式。

## 不可变身份与事务

- 新增迁移 `040_bid_package_output_identity.sql`，把输出绑定到输出配置修订号、来源快照 SHA-256、生成键和生成器版本。
- 生成键由冻结来源快照、生成器版本和输出配置修订共同计算；相同来源重复请求返回原八件套，不生成重复文件。
- 数据库事务先锁定正式报价包，再重新核对工作区、`QP-V`、`TS-V`、`CP-V` 和输出配置，八个文件全部写入后才提交。
- 任一文件写入、审计事件或来源核对失败都会整体回滚；检测到不完整或不同生成键的既有输出时拒绝覆盖。
- DOCX、PDF、ZIP 和 JSON 均记录 MIME、字节数和 SHA-256；ZIP 内另含附件清单，顶层 JSON 清单记录七个载荷文件及自身哈希存储规则，避免循环哈希。

## 权限和下载

- 只有机会中指定的项目负责人报价工程师可以对已批准 `QP-V` 执行生成；Administrator 不能代替项目负责人生成。
- 具备该机会访问权的技术成员只能看到和下载技术包 DOCX/PDF。
- 商务包、完整标书、附件 ZIP 和清单仅对具备该机会商务可见权限的人员开放；直接 URL 同样重新执行工作区和文件类型权限检查。
- 下载统一返回 `private, no-store`、`nosniff`、安全附件文件名和 `X-Document-SHA256`，并写入不可变下载审计事件。
