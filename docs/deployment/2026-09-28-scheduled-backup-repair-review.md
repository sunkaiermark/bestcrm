## 发现的问题

- 2026-09-28 的生产只读检查显示：现有完整备份最新为 2026-09-25，磁盘剩余 91 GB；主服务、邮件增量接收和 ClamAV 正常，历史邮件回填关闭。
- `/etc/cron.d/bestcrm-backup` 每天 02:30 直接调用 `/opt/bestcrm/scripts/backup-production.sh`；实际脚本在邮件增量接收仍运行时拒绝备份。日志连续出现 `Email intake is active; stop it before creating a consistent database/file backup.`。因此旧定时任务并没有按预期形成新备份。
- 旧备份脚本在写出清单后、独立校验前便可能执行保留期清理。不能把“生成了清单”当成“可恢复的安全备份”。

## 本地修复范围

1. `scripts/backup-production-scheduled.sh`：与发布共用互斥锁；拒绝正在回填、已有维护标志或服务不健康的状态；启用写入维护、停止邮件增量接收、等待在途请求排空，再调用生产备份脚本。无论成功还是失败，均尝试移除自己创建的维护标志、恢复邮件接收，并复核服务和健康状态；恢复失败时返回非零状态，不冒称成功。
2. `scripts/backup-production.sh`：备份清单生成后，先运行独立附件/邮件/上传归档校验器；只有校验成功才进入旧备份清理。校验失败时，仅删除本次新建且尚未验证的目录，不触碰已有备份。
3. `docs/deployment/templates/bestcrm-backup.cron`：将 02:30 定时入口改为受控脚本。旧 `backup-bestcrm.sh` 模板仅转调受控脚本，不再直接读取环境文件、裸跑 `pg_dump` 或自行删除文件。
