# BESTCRM 2026-09-30 发布候选验收记录

状态：本地代码与隔离数据库验收通过；只有在 Git 提交、不可变发布包、生产现场前置检查和生产备份验证完成后才可部署。本文件不等于生产已部署证明。

## 候选范围

- 销售负责人可在工程师上传同商机技术文件后建立/保存内部商务报价草稿，不等待技术方案批准；自动带入当前商机、客户、联系人，草稿语言按创建时登录语言冻结，来源绑定精确技术草稿、附件 ID、文件名与 SHA-256。支持多行产品说明、数量、单位、单价和草稿币种，保存时显式确认来源版本；新技术修订出现时提示重新核对。数据库记录每次草稿修订的不可改审计快照。
- 草稿独立于现有 `commercial_quotes` 和 `quotation_package_versions`。草稿保存不推进工作流，不生成可对客 PDF，不可从 CRM 邮件作为已批准报价发送；正式提交、签署、发送仍需既有技术及商务批准。
- 技术文件逐文件对客放行：技术经理对精确文件版本审批/撤回，销售仅从已放行的文件中明确选择报价包附件，并在生成/邮件发送时再校验文件身份、客户和放行状态。管理员临时技术自审代码具备过期门槛，但默认关闭，且自审技术文件不得对客放行。
- 工作台待办与计划快捷入口/详情，以及现有页面调整；见本次 Git 提交差异。
- `docs/standard-commercial-quotation-template-draft.md` 仍是对客报价单设计稿，不是 CRM 生产正式模板。

## 明确未交付与剩余风险

- 未交付正式商务报价模板的公司预设库、自动计算、对客 A4 PDF、报价签发/电子签署。草稿中的单位与币种仍是内部编制字段，不能代表公司已批准的商业条款。销售须待预设、签署服务与正式流程另行验收。
- 工程师上传文件目前沿用技术草稿中的“上传文件”类别，销售人工选择报价依据；没有自动识别文件是否为技术报价，更不会解析产品、价格。
- 技术文件对客放行的用途仍是自由文本并须人工审核；CRM 邮件里的普通本地附件不受精确技术来源门控，不得用其绕过审批。
- 管理员临时技术自审需要在生产环境单独设置开关与不超过七日的明确截止时间；部署代码不自动启用。
- 发布前重查线上版本、服务、磁盘、备份及当前生产数据；部署脚本必须生成并校验新备份。数据库迁移为前向新增表/约束；服务回滚与数据库回滚不是同一动作，保留备份且不做未经批准的数据删除。
