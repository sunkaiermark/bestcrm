# CAD发布的测试附件清理兼容处理

原v2026.11.01-01-rc.1在备份阶段发现800054附件150的原文件不存在，中止部署并恢复旧版本。此前经用户授权，附件150、151、154、156、157、253已经物理删除，数据库保留了移除原因、版本和活动历史。

兼容处理仅适用于商机55的上述六条记录及原清理原因。备份导出器读取/var/log/bestcrm-test-cleanup/800054-*.json，目录和凭据必须为root所有，不能是软链接，不能被组或其他用户写入。必须逐一匹配原文件路径、名称、编号、哈希、数据库移除状态和原因；任何其他文件缺失仍然失败，不根据retired状态直接跳过。

仅在原文件确实不存在时，以purged状态把完整清理凭据和其SHA-256嵌入附件证据清单。size为0表示本次归档不含原文件，originalSize保留数据库原大小。原始文件SHA-256和历史数据库记录保留。清单自身仍由备份manifest校验；恢复验证检查凭据内容，禁止purged文件意外出现在归档中，不尝试恢复被授权删除的字节。此备份不会恢复已物理删除的六份测试文件。

首次修复发布通过BESTCRM_ATTACHMENT_EVIDENCE_EXPORTER和BESTCRM_BACKUP_VERIFIER指定候选版本的已校验脚本，解决当前旧版本无法备份的问题。候选脚本借用当前版本依赖；package.json、lockfile、历史SQL及原部署/备份脚本必须保持一致。成功切换后，后续备份默认使用新版本的处理逻辑。无数据库迁移，不修改业务记录，不伪造空白原文件。
