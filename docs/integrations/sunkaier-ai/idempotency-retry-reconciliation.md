# 幂等重试与补账

事件在 clientId 内同时对 external_event_id 和 idempotency_key 建立唯一约束。事件预留、来源创建或追加、回执及审计在一个数据库事务内完成；冲突请求不会产生部分业务记录。

首次有效事件返回 201；相同事件、相同键及相同内容返回原回执和 200；键或事件号复用且内容不同返回 409。JSON 提交按签名的原始正文计算内容哈希，请持久化并重用原 JSON 字节。multipart 认证按完整原始 HTTP 正文签名，业务幂等按校验后元数据计算，文件哈希在元数据中，因此重试可更换 multipart boundary。

每次 HTTP 尝试都生成新时间戳和 nonce；保留业务事件号、幂等键和内容。nonce 防重放不替代业务幂等。

AI 发送前须将事件、字节、幂等键和待发状态持久化到自己的 outbox。网络超时不代表拒绝：先调用 reconciliation 查询原事件，或查询来源最小状态，再决定原键重试；不要换事件号规避重复保护。对账每批最多 100 个事件号，只查自身 clientId。

429、5xx 或未确认结果按原键重试，采用有上限的指数退避和随机抖动。client.mjs 提供签名调用和退避计算，不替代 AI 项目的持久化队列；SDK 不盲目自动重发。一般 4xx 要修正业务或认证，不重复轰炸。

相同外部线索号的新事件进入原来源链路；首次资料不覆盖，乱序事件按各自发生时间保留。归档后允许追加，仍保留归档状态；已删除来源拒绝追加，需 CRM 人工恢复。并发人工转 Lead 通过来源行锁及唯一关联约束只产生一次业务结果。
