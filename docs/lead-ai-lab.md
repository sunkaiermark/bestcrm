# AI线索实验版

本地独立实验，仅监听127.0.0.1，不连接CRM数据库、不自动收邮件、不执行正式审核。

## 版面

复用现有新建线索表单、产品分类和字段顺序，文字统一16px。主表单只新增一行“客户分析报告”，支持生成和朗读；AI输入、服务商及语音设置放在“AI填充”弹窗。不显示原文对照、字段依据或独立分析面板。后台保留原文、原始AI结果和引用，随实验草稿导出。

## 启动

node scripts/lead-ai-lab.mjs

访问 http://127.0.0.1:3011/ 。界面由 scripts/build-lead-ai-lab-assets.mjs 根据当前正式表单生成，修改后先运行生成脚本再重启实验服务。

## 实测配置

通过 LEAD_AI_LAB_ENV_FILE 指向独立实验配置文件，不使用生产环境文件，不将密钥提交Git或聊天。

- LAB_ARK_API_KEY：豆包密钥。
- LAB_ARK_MODEL：默认 doubao-seed-2-1-pro-260915。
- LAB_SEARCH_ENABLED=true：联网调查开关，需开通搜索权限。
- LAB_TTS_API_KEY：豆包语音独立密钥。
- LAB_TTS_SPEAKER：默认 zh_female_vv_uranus_bigtts，按账号音色权限调整。
- LAB_OPENAI_ENABLED=true、LAB_OPENAI_API_KEY、LAB_OPENAI_MODEL：预留OpenAI适配，启用前核对账号和地区资格。
- LAB_CALL_LIMIT：进程内付费请求上限，默认20；重启重置，不是持久月度预算。

未配置密钥时仅支持固定虚构样例演示，不能分析真实邮件。真实分析、联网搜索和豆包语音均需账号配置后联调。实验审核经理是本地占位选项，与正式用户无关；提交审核仅下载JSON草稿。附件上传尚未接入。

## 朗读

浏览器朗读与豆包语音分别标识。豆包语音单独计费并需确认发送朗读文本。播放控制在AI设置中。

## 验证

9项模拟接口测试覆盖字段依据、缺失留空、模型切换、搜索最小化和语音解析。浏览器验证表单填充、分类确认、原文隐藏、16px字号及视口宽度；不把模拟测试当作真实服务验证。
## 已固化的邮件衔接边界（2026-10-21）

实验版通过 emailAiDraftService 管理独立草稿状态 processing / ready / failed。只读邮件快照，按最新收件正文指纹检查过期。权限检查在分析和审阅前分别执行。现有邮件关联决定补充已有记录建议，不能按发件地址或模型猜测自动合并。

AI 不拥有邮件归档、垃圾邮件、已读、回复、线索创建、立项、审批、人员分配操作。正式衔接必须调用原有转线索及提交入口，不得绕过原有校验。人工确认字段与 AI 原始结果分开保存；初始需求采用人工确认的整理文本，原邮件保持在来源邮件。

本次实际运行范围：本机实验服务，内存草稿仓库，重启清空；审阅后导出 JSON。尚未接入正式邮件仓库、持久数据库或正式转线索接口，未启用历史邮件批处理。正式邮件中心页面和审批程序未修改。实际豆包提取、联网和语音需配置对应实验密钥再验收。
## 云端受控试用

独立地址 /lead-ai-trial，默认关闭。启用后仅允许 LEAD_AI_TRIAL_USER_IDS 或 LEAD_AI_TRIAL_USERNAMES 指定的已登录活跃账号。复用正式 CSRF 与维护锁；禁止匿名访问，不增加菜单，不改变邮件及线索页面。AI来源为手动粘贴，未自动读取邮箱或创建业务记录。审阅结果仅下载，不能作为正式提交流程已完成的证明。

通过 sudo bash scripts/configure-lead-ai-trial.sh 隐藏输入密钥，存入 root 600 环境文件。此脚本会重启应用并检查健康；不配置语音，不改变邮件接收服务。联网调查有单独确认。默认每次服务进程运行最多5次付费请求（包含失败）；进程重启会清零，并发仅1次。这是试用次数限制，不是平台金额限额。语音及联网工具的服务权限、计费以提供商配置为准。

草稿在内存中，每位账号保留最新一份，重启清空。试用内容不自动回写正式线索或商机。撤回试用：在 /etc/bestcrm/lead-ai-trial.env 将 LEAD_AI_TRIAL_ENABLED 设为 false 后重启 bestcrm。不要输出此文件或把密钥放入工单、日志、截图或代码库。
