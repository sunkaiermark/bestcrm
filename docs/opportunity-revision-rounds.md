# 商机多轮修订、逐版审批与最终签约

商机页新增“修订与最终报价”。每轮保留客户反馈、正式报价及其审批依据，最终合同绑定客户明确接受的报价版本。

## 操作流程

1. 第一轮完成技术方案和对应价格核算，逐文件提交、同意或驳回。未全部同意时可准备商务报价草稿，不能提交正式报价。
2. 提交商务报价形成独立版本，冻结本轮技术方案、核算版本及文件摘要。正式报价按原权限审批、签发。
3. 客户反馈后，在“客户反馈／发起新修订”填写变更要求：
   - 技术变更：形成新技术版本；对应价格核算必须重新修订并审批。
   - 商务变更：保留已批准技术和核算依据，仅修改报价价格或条款。
4. 新轮次继续提交、审批报价，可重复多轮。审批中的报价先完成审批或驳回，不能直接跳过。
5. 销售负责人或管理员在“确认客户最终接受的报价”选择当前轮次已批准的商务方案，或已签发的正式报价，并填写客户确认依据。
6. 随后按原流程记录赢单、上传合同并提交合同审批。合同冻结最终报价、轮次、客户确认记录和技术核算依据。合同批准后的项目执行条件不变。

## 文件与历史版本

- 每个文件独立一行、独立审批；一份被驳回不改变其他文件。
- 已批准工作包选择“新修订”，可替换选中的原批准文件，其余未变更文件沿用。可在同一新版本内继续替换其他文件。
- 修改后的文件需重新提交、审批；历史原文件、原审批结果保留。
- 新轮次开始后，历史轮次正式报价仍可查阅、下载，但不能再次签发、发送为当前报价或用于当前合同。
- 客户接受记录不能直接覆盖；客户再次变更时发起新一轮。
- 历史报价未自动编造轮次；已有历史合同保持原绑定。后续新合同需完成当前轮次最终报价确认。

## 实施与验证

新增数据库迁移 `134_opportunity_revision_rounds.sql`，包括轮次、报价审批依据、技术核算关联和最终合同快照。应用与迁移必须一起发布。

自动化测试使用隔离数据库和虚拟账号，覆盖三轮往返、技术变化使旧核算失效、连续替换多个文件、逐版冻结、正式报价审批与签发、旧版本限制、最终合同绑定、权限、CSRF和重复确认。没有向客户实际发送邮件，也没有修改生产商机。


## 已确认的需求与文档版面

商机页面按“基本信息 → 客户需求 → 往来邮件 → 技术方案 → 价格核算 → 商务方案”排列；合同与审计记录继续保留在后面。

- 初始需求标记R0，后续客户变更依次为R1、R2、R3。轮次与文档版本分别编号。
- 客户需求包含需求文字、需求附件和可选择的来源邮件；初始需求的补充文字仍可在立项前保存。
- 切换需求时，技术与价格核算按对应轮次展示。当前需求可操作，历史需求使用冻结快照，只提供预览与下载。
- 文件表格显示工作包、提交文件、需求、版本、负责人、版本来源、状态、操作；沿用文件明确标明来源，逐文件审批操作保持原流程。
- 正式报价提交后，需求文字、附件及商务文件不再追加到原依据；新增客户要求应创建新需求。
- 最终报价与合同保留当前需求及此前的客户要求链、技术核算文件摘要与商务文件摘要。
- 历史未关联需求的资料单独保留，不自动猜测归属。

所有应用文字保持16px；桌面与手机横屏使用相同栏目和表格。
