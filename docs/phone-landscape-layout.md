# Phone landscape desktop workspace

This local revision supersedes the previous phone card/single-column navigation mode for Android, iPhone and iPad browsers. A head script sets a consistent 1280px desktop layout viewport before rendering; pinch zoom remains enabled. Existing desktop sidebars, columns, table rows and form actions are retained regardless of a phone's folding state. Portrait shows a rotate-to-landscape prompt without reloading or replacing form nodes. Desktop browser viewport metadata and DOM are unchanged.

On phone opportunity detail pages, long record lists lose their nested vertical limit/scroll containment. Read-only same-origin email frames expand to their content height, accounting for text bounds, paragraph/body margins, padding and iframe borders. This avoids tiny remaining iframe scroll ranges that consume the first touch gesture. Original email sandbox/CSP remain unchanged; Office editors and foreign-origin frames are not modified. Only the outer page owns normal vertical scrolling, while wide tables retain horizontal scrolling.

Validation: 13 focused regressions passed for phone bootstrap, rotation and form identity, desktop behavior, legacy layout isolation, form submission, file approval and public health. Chromium Android simulations at 844x390 and 1100x650 both produced the same 220px sidebar plus 1060px main area with no card conversion. A 390x844 portrait case showed the rotation prompt. Native touch events starting over an email frame moved the outer page from 3083px to 3300px while the frame scroll offset stayed zero. An unsaved work-package title survived portrait/landscape rotation. Long sample lists had equal content and client heights. These are local browser simulations; the reported Honor device (user supplied model text: 荣耀1010) has not been physically tested, and no specific affected opportunity URL was provided.

No migration or server configuration changes. Existing phone layout assets remain as a fallback for narrow non-phone desktop windows; the new phone bootstrap skips their card/menu transformation. Production device acceptance follows deployment of the release candidate.
