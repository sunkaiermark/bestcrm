# SUNKAIER 标准商务报价模板（审核草案）

状态：对客报价模板仍仅供内部审核，不是已发布的 CRM 正式模板，也不得直接发送客户。销售“报价草稿”录入、多行保存、卖方主体选择和商务条款空目录结构已在本地实现；本地待发布改动新增八类条款的草稿／异人审核发布／停用管理，以及带明显“内部草稿、未批准、未签署”标识的 A4 PDF 预览。八类条款仍无公司批准的实际文案。该预览不生成正式报价编号，不含电子章，不进入邮件发送；正式审批 PDF 输出及电子签署尚未实现。报价语言由用户登录前选择的 English／中文决定；创建内部草稿时冻结该语言，未来每个正式报价版本只输出一种语言，不做中英双语并列。最终交付目标为已电子签署的 PDF。

文案管理权限按“商务经理拟稿、总经理审核发布、作者与审核者不同账号”执行。仅有管理员角色不能代办拟稿或发布；若同一账号同时具备商务经理和总经理角色，仍不得审核自己拟稿的文案。此权限仅适用于标准文案管理，不替代商务报价本身的审批链。

适用范围：普通商机报价。招标书、技术协议和合同分别走其受控文件流程；本模板只引用已批准的技术范围，不复制或改写技术结论。

### 商机入口与草稿时点（2026-09-30 确认）

- 商机销售负责人点击“商务报价”进入本模板；商务报价由销售填写，不再由工程师代填。工程师上传技术报价文件后，销售即可创建和保存商务报价草稿，不必等待技术经理批准。
- 模板从当前商机自动带入商机编号及名称、客户与联系人、销售负责人，以及销售所选的工程师上传技术报价文件及其不可变版本标识。该文件仅作为销售编制依据；不自动识别或复制文件中的产品、价格和条款。产品明细、数量和单价由销售逐项填写，商务条件从同语种已发布标准文案中逐项选择并确认；当前目录为空时不得伪造默认条款。
- 录入页提供“添加行”和“保存”操作，以支持多产品草稿。保存不得改变商机工作流阶段，也不得产生可对客发送的文件。
- 技术版本尚未批准时，商务报价只能停留在内部草稿。正式提交审批、生成对客 PDF、电子签署及发送仍须满足技术批准和其他现行控制；不得以草稿入口绕过权限或文件版本检查。
- 若作为编制依据的技术报价文件出现新版本，草稿应提示销售重新确认所用版本；已批准或已发送的报价不得被静默追改。

### 技术文件对客放行程序（业务已确认；本地实现待发布验收）

1. **逐文件分类**：工程师上传的每份技术文件及每个修订默认标为“内部使用”。工程师可对其中一份独立修订发起“拟对客使用”申请，填写对应商机、客户、用途与文件版本；内部计算、成本、原始图纸或设计记录不能因与客户版同属一个技术草稿而自动外发。若一个文件混有内部内容，须先制作脱敏的客户版新文件。
2. **独立审批**：技术经理核对客户版内容、适用客户与用途后，对该精确文件版本作“批准对客／退回”决定，记录审批人、时间和意见。技术方案内容批准与文件对客放行是两项不同决定；临时管理员自审测试产生的技术批准不构成对客放行。
3. **销售编制与选择**：销售可在有权访问时引用内部技术报价版本编制商务报价，但该引用只在 CRM 内留痕，不出现在对客 PDF，也不自动附送原文件。签发时，销售只能从本商机、该客户已获对客放行且仍有效的文件版本中明确勾选附件，并对照审批记录中的用途；无须附技术文件的报价可不选择。
4. **发送前强制复核**：服务端在报价包生成及 CRM 邮件发送时再次校验放行状态、文件版本、SHA-256、商机／客户与实际附件一致；只隐藏前端选项不足以保证安全。任何一项不匹配则阻止生成或发送。用途文本尚需人工核对；若要按用途自动阻断，须先确定受控用途分类。
5. **历史与撤回**：新修订不继承旧修订的对客许可。撤回许可只阻止未来发送，不改写已发送的客户文件和归档证据；已经技术批准的旧文件在完成逐文件复核前，迁移后仍按“内部使用”处理。
6. **交付留痕**：记录最终对客 PDF／技术附件的不可变版本、校验和、批准记录、实际发送邮件及时间。新产品研发结论的对客使用申请和实际文件版本绑定仍遵守其独立规则，不因本流程自动授权研究原件外发。

## 三、CRM 内部控制（不出现在对客正文）

1. 模板本身维护修订与审核；只有已发布修订可生成项目报价草稿。生成时冻结模板修订，不追改历史报价。
2. 客户资料、商机、币种、技术版本可在有权限时预填；价格、税费、付款、交期、贸易术语、质保和偏差必须由商务负责人逐项确认，不能采用未经批准的默认商业承诺。
3. 草稿可反复编辑；提交审批时冻结价格表、商业条款、附件版本与校验和。审批通过后生成待签 PDF；只有签署完成的正式 PDF 才能进入 CRM 对客发送流程。
4. 修改已发送报价必须创建下一正式版本，重新审批和电子签署，记录内部修订原因及客户可读的变更摘要；不修改已发版本或邮件附件。
5. 项目明细、选配、费用和税额必须与报价总额一致；未填写的必填字段和未解析占位符阻止提交。

## 四、PDF 输出与电子签署

1. 审批通过后，以冻结的报价内容和选定语言生成单语 PDF，固定报价编号、版本、附件版本和内容校验和。待签 PDF 标为“待签署”，不能作为正式报价发送客户。
2. 产品明细可以有多行并跨越任意数量的 A4 页面。第一页显示完整报价抬头、供应商和客户资料；续页使用简化抬头，重复 Logo、报价编号、Ref.（商机号）、报价版本号与明细表头，并连续编号产品行。这三个编号是独立字段，不能以商机号替代报价编号。单行明细不得在页尾被截断。报价总额、商务条件和签署区作为一组放在最后一页；空间不足时另起末页。每页显示“第 X 页／共 Y 页”。“添加行”“保存”等编辑控件不得出现在 PDF 内。
3. 所选授权签署人须在 CRM 接入的电子签署流程中确认并完成签署；仅在 PDF 上叠加签名图片、印章图片或打字姓名不算完成电子签署。签署服务及签署人的授权范围须在上线前确定。
4. 签署完成后，CRM 保存不可覆盖的已签 PDF、签署状态、签署人、签署时间、签署记录及最终文件校验和；对客邮件绑定这一精确文件版本。签署失败或文件校验不一致时阻止发送。
5. 若需补签、换人签署、修改内容或更换附件，创建新的受控报价版本并重新审批、生成 PDF 和签署，不改写已签或已发送文件。

## 五、发布前待确认

- 每份草稿使用创建时的登录语言；若需另一语言，对同一商机另建受控修订，不翻译或覆盖已批准／已发送文件。
- 卖方法定主体、公司地址、网站、对外报价联系人及其电话／邮箱、Logo、授权签署人名单、电子签署服务及适用地区的合规审查。
- 价格表是否需要折扣、税率、汇率、不同币种或分阶段价格。
- 付款、交期、贸易术语、质保和有效期的公司批准预设及管理人；未批准的候选项不得出现在可选下拉中。
- 普通报价与投标文件是否使用不同模板，哪些附件属于必选。

本草案不包含真实客户、价格、银行账户、税率或法律承诺。内部草稿目前只绑定商机、客户当前资料、精确上传技术文件版本、录入语言及产品明细；币种为内部草稿用 ISO 代码输入，不能当作已批准的对客币种预设。草稿只有带防误用标记的 PDF 预览，没有正式审批、签署或发送入口，不会自动改变商机阶段。PNG 印章不能替代实际电子签署；待公司条款、签署服务、授权签署人及审批链对接验收后，才能开放正式 CRM 报价 PDF 与签发范围。

技术文件对客放行已在本地代码中按文件 ID、商机、客户和 SHA-256 绑定，并在报价附件选择与 CRM 邮件发送时复核；尚未部署。申请时的“用途”目前为审批记录中的文字说明，尚未变成机器可校验的用途分类。普通本地邮件附件也不在此技术文件来源门控之内，这两项在正式发布前需作为剩余风险单独评审。
