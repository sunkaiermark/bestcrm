状态：本地代码，待用户审核。未提交、未部署；生产数据库未运行 083/084/085 迁移。基线：用户确认线上 `v2026.09.25-02-rc.1`，本地 HEAD 同名标签。2026-09-27 补入用户确认的代理、暂停、终止与恢复政策。

## 业务边界

- 一个独立 NPD 课题拥有连续、不可覆写的概念修订。新修订即使只是普通编辑，也不会静默继承旧批准；团队可重新送审。正式设计交接只授予**当前**修订的一次资格，并不创建产品工程、CAD、BOM、Mixers 记录或对客版本。
- 一页式概念包保存：问题、应用场景、范围、候选方向的优势与取舍、拟选方向、关键假设、已知风险、探索证据、下一步投入，以及可选的客户/商机背景。建修订可先不完整；送审前服务层逐字段验证。这里的证据是文字来源，P3 才实施受控文件附件。
- 送审时锁定精确修订。技术经理只能对当前待审修订作 `approved` 或 `revise_required` 决定；负责人/销售/一般管理员没有批准权。修订、送审、决定、交接以及审计事件均不可改写或硬删。
- 用户已确认技术经理可以批准自己编写或提交的概念包，但必须填写独立自审理由。数据库会核实并强制记录 `is_self_review`、`self_review_reason`。审批决定仍须填写业务理由。
- 技术经理缺席时，只有**另一位在职技术经理**可代理其指定课题的概念评审。管理员仅记录被代理人、代理人、起止时间、原因及撤销，不取得概念代签权。到期、撤销、任一经理停职或被代理人不再属于课题，代理立即失效。
- 暂停、终止、恢复是**课题生命周期决定**，不等同于概念修订批准。课题负责人提出并填写原因，管理员批准或驳回并填写原因；负责人兼任管理员可自批，但须另写自批理由。暂停和终止都可恢复，恢复至发起暂停/终止前被记录的阶段；暂停后再终止仍保留同一恢复阶段。未批准的决定不改阶段。

## 权限与门控

| 操作 | 当前 P2 保守规则 | 检查位置 |
| --- | --- | --- |
| 查看概念修订/门控状态 | 在职课题成员，或任期内的在职技术经理代理人 | 服务/仓储；不可见对象返回 404；代理仅取得该课题的概念视图，不取得原始研究资料权限 |
| 建修订、送审、请求交接 | 在职课题负责人且有效成员 | 服务/仓储；写操作要求 `expectedRowVersion` |
| 最终概念决定 | 在职 `technical_manager` 且为课题有效成员，或经管理员正式任命的有效代理技术经理 | 会话角色、仓储实时角色/成员/任期/撤销核查、数据库触发器；决定行记录代理任命 ID |
| 正式设计交接 | 当前修订已有 `approved` 决定，阶段为 `concept_review` | 仓储事务、数据库交接触发器与阶段触发器 |
| 请求暂停/终止/恢复 | 在职课题负责人且有效成员 | 行版本、当前阶段、唯一待决申请；恢复到记录的原阶段 |
| 审批生命周期申请 | 在职管理员 | 服务/仓储/数据库；自批须独立理由；管理员无概念方案批准权 |
| 任命/撤销代理 | 在职管理员 | 双方必须是不同的在职技术经理，被代理人为该课题有效成员；任期、重叠与撤销审计 |

`technical_manager` 的全局角色本身不能访问所有课题；有效成员或经管理员记录、仍在任期内的课题代理任命才授予概念范围。成员授予/撤销以及完整对象权限管理仍属于 P4，当前没有开放课题创建或成员变更的 HTTP 入口。生产数据不会因本阶段自动生成课题。

## 状态序列与并发

```text
idea/exploration → 不可变概念修订 → 送审(concept_review)
    → 技术经理批准 → 当前修订具备交接资格 → 一次交接(detailed_design)
    → 技术经理要求修改 → exploration → 下一修订重新送审
```

当已批准或已交接的课题创建下一修订时，事务内回到 `exploration`，当前交接资格失效；旧决定和旧交接只作为历史事实保留。所有写操作先锁课题行、核对客户端的行版本，再校验当前修订、成员和权限。重复请求使用幂等键；相同键/内容可返回原决定或交接，不同内容与并发过期请求返回 409。数据库还禁止未取得**当前**修订批准及交接记录就把课题置为 `detailed_design`。

生命周期另行按 `申请 → 管理员决定 → 阶段变更` 处理：待决申请唯一；批准时必须还是原阶段和原行版本，驳回过期申请仍允许，以免卡死；直接 SQL 修改暂停/终止/恢复阶段会被数据库守卫拒绝。所有申请、决定、代理任命、撤销和审计事件只追加不可覆写。

## HTTP 契约

所有路径复用现有登录会话、CSRF 和写维护保护，没有新增侧栏入口：

| 路径 | 用途 |
| --- | --- |
| `GET /development/topics/:id/concept-gate` | 权限内读取当前修订快照、决定和交接资格 |
| `GET /development/topics/:id/concepts/:revisionId/preview` | 只读、双语、转义后的精确修订预览 |
| `POST /development/topics/:id/concepts` | 创建下一不可变修订 |
| `POST /development/topics/:id/concepts/:revisionId/submit` | 送审当前完整修订 |
| `POST /development/topics/:id/concepts/:revisionId/decision` | 技术经理批准或要求重审 |
| `POST /development/topics/:id/design-handoffs` | 负责人请求一次当前修订的正式设计交接资格 |
| `GET /development/topics/:id/lifecycle` | 负责人或管理员查看阶段及申请/决定历史 |
| `POST /development/topics/:id/lifecycle-requests` | 负责人申请暂停、终止或恢复 |
| `POST /development/topics/:id/lifecycle-requests/:requestId/decision` | 管理员批准或驳回；自批需额外理由 |
| `GET/POST /development/topics/:id/reviewer-delegations` | 管理员查看或记录指定课题的技术经理代理任期 |
| `POST /development/topics/:id/reviewer-delegations/:delegationId/revoke` | 管理员撤销代理，保留历史 |

未登录 `401`，无权 `403`/对象不可见 `404`，缺字段 `422`，过期修订/版本及重复冲突 `409`。创建、送审、决定与交接均没有绕过服务的前端快速通道；只读预览页也不包含发布图纸、对客交付按钮。
