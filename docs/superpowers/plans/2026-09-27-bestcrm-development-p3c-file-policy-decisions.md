# BESTCRM 新产品开发 P3c：研发资料权限与文件政策待确认稿

状态：三项原则性建议、逐文件授权主体和每课题累计容量已获用户确认，SOLIDWORKS 原生文件明确不纳入 CRM。P3a、P3b 已在本地获审核通过；P3c 研发文件入口已有本地代码但受 `DEVELOPMENT_FILES_ENABLED=false` 默认关闭，未提交、未部署，也未获上线授权。资产发布与对客引用仍未开放。

## 现有实现及风险边界

- CRM 通用 `MAX_UPLOAD_MB` 默认 3072 MB；技术草稿入口另限单文件 25 MB，技术文档入口限 50 MB，外发邮件默认总量 25 MB。这些上限服务于不同流程，不能自动作为研发附件上限。
- 已有邮件原始归档使用的 ClamAV 扫描适配器，但没有研发资料的扫描配置、隔离状态或生产可用性证明。扫描器不可用或返回错误时，研发文件应保持不可使用，而非视为安全。
- P3a 仅记录带 `blocked_pending_policy` 的元数据；没有实际文件落盘或读取路径。P3b 的候选审核记录也不赋予文件读取或资产发布权限。
- [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)建议使用业务必要的格式允许列表、文件大小限制、实际类型校验、服务端生成的存储名、受控存储及可用时的恶意内容扫描。现有代码是否满足这些要求须在 P3c 实现及测试中逐项证明。

## 建议确认的规则

**逐文件授权规则已确认**：客户保密／受限文件只由当前在职、有效且为课题成员的课题负责人，向本课题在职有效成员授予或撤销读取权；上传者自动保有本人读取权，且必须继续满足在职有效成员条件。管理员默认只能看必要的元数据。任何过期成员资格都立即终止读取。重新加入课题后是否恢复过去的授权尚未确认，实现时先按不自动恢复的安全边界处理并单独验收。

客户保密资料的紧急管理员访问是否需要“双人批准”、由谁批准，以及可见元数据范围，均须另作明确决定；在此之前不得设计可绕过课题授权的管理员下载入口。研发附件不得默认发送给外部 AI。P3b 的 `endorsed` 决定仍不能直接供商机对客引用。

**工程文件边界已确认**：`.SLDPRT`、`.SLDASM`、`.SLDDRW` 不在 CRM 上传允许表，也不开发 CRM 内的原生模型预览。未来由工程/PDM 系统管理其权威原件与版本；CRM 可以管理有权限的研究说明及必要的 PDF/STEP 等衍生或交换文件。跨系统受控引用须另行设计和审批，当前不假设 PDM 接口已经存在。

本地已先加入未接入路由的 `developmentFileInspectionService.mjs` 与 `developmentPrivateFileStore.mjs`：固定首批已列明的非原生格式、100 MiB 单文件上限、内容标识检查及扫描失败关闭，并将通过检查的文件提升到不可公开访问的随机路径。它们不落库、不生成用户可读取路由；读取辅助函数只验证路径与完整性，调用方仍须先做数据库授权。迁移 `088_development_restricted_file_grants.sql` 为受限文件建立只追加、可撤销、绑定有效成员身份的授权审计，不等同于文件激活或下载权限；在隔离 PostgreSQL 中已通过授权负向测试。真正开放上传还需文件/数据库提交补偿、文件激活记录及生产扫描器验证。

现有生产备份脚本会打包整个受控上传根目录。本地已补充排除 `development/.incoming` 与 `development/.staging`，且备份校验器拒绝包含这些临时目录的归档；已激活的研发原件已纳入逐文件库存与隔离恢复哈希校验，不再仅依赖整包校验。

容量确认后的本地实现：迁移 `089_development_material_file_activation.sql` 在数据库事务内按课题行锁检查 100 MiB／文件与 1 GiB／课题（含所有版本），批量与并发插入也不可绕过；只有带干净扫描记录的独立激活事实才允许进入读权限判定。内部研究由课题有效成员读取；受限资料仅上传者或本课题有效成员持有效逐文件授权时读取，管理员与技术经理身份本身不构成原件权限。`developmentMaterialFileService.mjs` 按此规则查库、验证磁盘 SHA-256、记录读取审计，尚未挂载下载路由。现有附件备份库存已纳入已激活研发文件，并在隔离恢复时逐件核对大小与哈希；临时文件仍被排除。

本地又补充未挂路由的 `developmentMaterialUploadService.mjs`：仅清洁且带有效引擎／签名版本和本次扫描时间的文件，才能进入数据库事务；事务中先建立版本与激活，再提升并核对私有文件，最后提交。提升失败会回滚版本、激活及配额占用。协调流程结束会安全清理其 `.incoming` 随机命名源文件；进程崩溃留下的临时文件由审计识别。若在文件提升之后丢失数据库提交响应，不能安全判定提交是否成功，因此不删除已提升的私有文件；授权读取仍只看已提交激活。只读 `development:files:recovery-audit` 会识别已激活文件缺失／损坏、未登记的私有文件及超过 24 小时的暂存文件，供人工核查，不自动删除历史版本或疑似孤儿文件。入口仍未挂载。

隔离 PostgreSQL 已验证协调流程提交、提升失败回滚、权限读取；故障注入验证扫描器缺失、超时、签名版本无法确认及提交响应丢失时的关闭行为。全套本地测试通过。此项测试不代表生产环境的 ClamAV 服务或签名库已核验。

P3c 本地又加入受开关控制的 `/development/topics/:id/materials` 专用研究资料页、资料登记、版本上传、可见版本列表及受控预览／下载。所有入口先检查在职有效课题成员；列表只返回创建者自己的空资料记录和已获读取权的文件版本，受限文件名不会泄露给无授权成员。Multipart 上传在落盘前要求会话 CSRF 头，限制 100 MiB、单文件、扩展名／声明 MIME／内容标识、扫描；原件落入私有 `.incoming` 后由协调流程清理。PDF 和常用图片允许受控内联预览，其他格式仅下载；每次读取重新鉴权、验证哈希并写访问审计。管理员、技术经理或商机身份本身仍不构成研究原件权限。单独的课题五区详情页仍属 P4，当前页是 P3c 的局部验收入口，不代表整套研发 UI 完成。

本地路由测试和隔离 PostgreSQL 路由测试已覆盖未登录、非成员、跨课题、CSRF 缺失、声明 MIME 不匹配、受限未授权、授权后读取、撤权后拒绝及列表隐去文件名。P3c 又补了课题负责人专用的受限版本管理区：只列本课题已激活的受限版本、在职有效成员和当前有效授权，授予与撤销都要求填写原因；服务器再次核对负责人及课题归属，数据库触发器继续记录不可修改的审计。上传者本人的成员资格读取不因撤销其他授权而改变。浏览器已实测授予／撤销表单与刷新状态，390px 窄屏无横向溢出、控制台无错误。

隔离环境已完成一次**合成数据**的整库与研发附件联合恢复演练：迁移后的源数据库写入受限研究 PDF 和授权，将 PostgreSQL 全库导出、文件归档及附件库存一同校验，再恢复到第二个空数据库和私有文件目录；哈希、记录数、恢复后读取及撤权后拒绝均通过。这证明本地恢复路径，但不等于已经用生产备份在隔离主机做过恢复。生产 ClamAV 服务状态由用户回报为 active，根分区和上传目录所在分区可用 91 GB；BESTCRM `ubuntu` 服务账号对非敏感 `package.json` 的 `clamdscan --fdpass` 试扫已返回成功标记。生产 `clamdscan --version` 只返回客户端本地引擎 `1.5.3`，不返回病毒库版本；`clamd.conf` 明确关闭 `VERSION`，本地 socket 为 `/var/run/clamav/clamd.ctl`、属主 `clamav:clamav`、权限 `0666`，而 `ubuntu` 不在 `clamav` 组。用户在生产环境只读查询 `nVERSIONCOMMANDS` 成功返回守护进程实际版本 `1.5.3/28135`。因此本地研发文件扫描器改为通过已配置的 Unix socket 在每次清洁扫描前后查询实际加载的签名版本；版本缺失、查询失败或扫描期间变化均 fail-closed，不再依赖客户端本地版本，也无需现在修改生产 ClamAV 配置。该路径已用模拟 socket 和扫描器测试，尚未在部署后的 BESTCRM 代码中完成真实上传验收。进一步只读检查确认 `LocalSocketGroup clamav`、`LocalSocketMode 666`、`EnableShutdownCommand false`、`EnableReloadCommand false`；`VERSIONCOMMANDS` 中列出命令并不代表已启用，不能误报为任意用户可关闭扫描器。现有 `0666` socket 仍允许本机其他账号连接与发起扫描，是独立的最小权限加固事项；不可在未核对所有使用者并安排回退前直接收紧为 `0660`，否则可能中断现有扫描。生产备份的隔离恢复、人工核查后孤儿文件安全处置流程、socket 最小权限决策及正式上线审批仍未完成。因此 `DEVELOPMENT_FILES_ENABLED` 必须保持关闭，不提交、不部署。

### P3c 恢复审计与隔离处置规则

`development:files:recovery-audit` 只读；任何异常都使 `ok=false`，包括存在持久化但未激活的文件版本。审计结果不是删除授权，尤其不能仅凭文件超过 24 小时就清理。正式处置前须保留审计输出、版本与文件哈希、数据库记录、上传任务状态及一份已验证的备份，并排除同时进行的上传或不确定的数据库提交。

- **已激活文件缺失或哈希不符：**暂停该版本的使用，核对审计与备份，只能从经过隔离恢复验证且哈希匹配的备份修复；不能用同名文件替换，也不能删去数据库版本以掩盖损坏。
- **有版本但未激活：**作为持久化状态异常调查事务与审计，不自动激活、不自动删除版本或文件。
- **未登记的私有文件：**可能是提交结果不确定时留下的原件。再次审计并核对数据库和写入任务后，方可提出隔离方案；隔离位置、保留期限与最终删除须另行审批，不由审计脚本执行。
- **过期暂存文件或意外目录项：**先排除在途写入、符号链接及路径异常；仅报告，不自动移动或删除。任何处置后都要重跑只读审计和读取权限／哈希验证。

生产备份在隔离环境的完整恢复演练仍未执行；本节只冻结安全处置判据，不声称已完成生产数据恢复或清理。

## P3c 的最低验收边界（规则确认后才实施）

1. 成员资格撤销、跨课题 URL 猜测、仅有技术经理/管理员/商机访问权、受限文件未获明确授权时，列表、预览、下载和直链均拒绝，且不泄露文件名与内容。
2. 超限、伪装类型、宏/可执行内容、压缩包、恶意或扫描失败、路径穿越文件名、重复上传与中断写入均有明确结果；不得留下可读取的孤儿文件。
3. 同名不同内容形成新版本而非覆盖；每版绑定服务器计算的 SHA-256、大小、扫描结果与审计。下载重新鉴权、检查文件存在和完整性。
4. 临时隔离数据库与文件根目录完成故障注入、备份及恢复演练；确认生产环境扫描器和容量，再另行申请上线批准。
