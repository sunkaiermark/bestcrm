# BESTCRM 新产品开发 P4a：课题入口与成员工作区

状态：本地实现，未提交、未部署、未启用。2026-09-27 用户再次确认线上仍为 `v2026.09.25-02-rc.1`，本地 HEAD 与该标签相同。P4a 不是 P4 完成，也不是新品开发模块上线授权。

## 本段范围

- 课题总览只列当前在职有效成员可见的课题；详情同样按对象权限查询，不因管理员、技术经理或商机关联而扩大研究可见性。
- 新建课题沿用 P1 独立 `NPD-` 编号、来源和多选产业方向，创建者自动成为负责人及成员，不要求先有商机。**用户已确认所有在职员工均可创建**，不另限销售或技术职务；停用账号不得创建。整个 P4a 入口仍由 `DEVELOPMENT_WORKSPACE_ENABLED=false` 默认关闭，代码完成不等于上线授权。
- 成员由用户已确认的规则管理：仅当前在职、仍是有效成员的课题负责人可邀请在职员工或结束其他成员资格；负责人不能移除自己；关系与事件审计只追加。停用账号的未终止成员资格仍向负责人显示，以便其结束资格；停用期间不可读取，重新启用后若资格已经结束也不会恢复访问。P4a 暂用 `member` 作为新成员职责标签，不推定销售、工艺或设备专业职权。
- 本段不开放负责人移交、商机关联/解除、结论资产发布、对客引用、产品工程或 Mixers 集成。课题详情只有概况与成员管理；冻结的五区页面尚未完成。研究文件仍由独立 `DEVELOPMENT_FILES_ENABLED=false` 开关保护。

## 代码与安全边界

- `src/routes/developmentTopicRoutes.mjs` 在独立开关开启且仓储可用时才挂载；现有会话、全局 CSRF 与写维护保护仍适用。
- `src/repositories/developmentRepository.mjs` 新增成员范围内的列表/详情查询及负责人事务化成员变更。查询连接 `users.is_active` 与未终止的 `development_memberships`；越权对象返回 404。成员邀请在事务内检查负责人、有效成员与目标员工状态；并发重复邀请只允许一条有效成员关系。
- `090_development_owner_membership_guard.sql` 阻止直接 SQL 结束当前负责人的有效成员资格；不修改现有 CRM 客户、商机、邮件或产品分类表。
- 页面输出使用 EJS 转义，响应 `Cache-Control: no-store`。成员候选列表只向有效课题负责人查询。旧研究资料的逐文件授权不会因普通成员加入而自动建立。

## 已验证与后续

- 路由测试覆盖开关关闭、匿名访问、独立建课题、字段错误、成员范围展示、HTML 转义和直接接口拒绝。
