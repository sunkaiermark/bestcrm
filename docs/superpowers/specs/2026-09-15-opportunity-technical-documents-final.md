# Opportunity Technical Documents — Final Specification

Date: 2026-09-15
Frozen implementation baseline: `ac2033c50950e103999870de903dbadbaaa9f6c4`

## Scope

An Opportunity may contain more than one product category and more than one equipment item. The assigned Quotation Engineer may produce three kinds of customer technical material:

1. `Datasheet`
2. `Technical Agreement`
3. `Bidding Document`

The existing `TS-D` / `TS-V` technical-solution approval history remains unchanged. This feature is an additive document workspace.

## Product categories

The controlled product-category catalogue is:

- 搅拌机
- 切胶机
- 研磨机
- 蒸汽管式干燥机
- 管束干燥机
- SK3000E 捏合机
- SK3000S 捏合机
- SK3000F 捏合机
- 刮膜蒸发器
- 撬装设备

Each standard template belongs to exactly one document type and, for new templates, exactly one controlled product category. This creates a maximum matrix of 30 active standard-template slots. Template revisions retain the existing draft, review, publish, retire, and immutable-history controls.

## Opportunity equipment

- The Quotation Engineer records equipment items inside the Opportunity.
- Each item has a stable item number, product category, equipment name, optional model, quantity, and structured key/value technical parameters.
- Equipment items are never hard-deleted. An item may be archived, while prior document snapshots remain readable.
- Updating an equipment item affects only future generation. It never changes an existing formal document version.

## Document composition

- A Datasheet is tied to exactly one equipment item.
- A Technical Agreement may combine one or more selected equipment items.
- A Bidding Document may combine one or more selected equipment items.
- Generation resolves the current published template for every selected product-category/document-type pair.
- Generation is blocked when any required published template slot is missing.
- The generated project copy is independent of its master template.

## Identity and versioning

System document codes are deterministic:

- Datasheet: `{OPPORTUNITY-NO}-{ITEM-NO}-DATASHEET`
- Technical Agreement: `{OPPORTUNITY-NO}-TECHNICAL-AGREEMENT`
- Bidding Document: `{OPPORTUNITY-NO}-BIDDING-DOCUMENT`

The first explicit save creates `V1`. Every later explicit save creates `V2`, `V3`, and so on; no formal version is overwritten. Working selections and external edits do not create a formal version until the user chooses the save-version action.

Each version freezes:

- selected equipment identities and quantities;
- technical parameters;
- product-category names;
- source template IDs, codes, names, and exact published revision numbers;
- an editable Office source file;
- a matching PDF snapshot;
- SHA-256 hashes, actor, timestamp, creation method, and change summary.

## Hybrid editing boundary

- V1 is generated by CRM as editable DOCX plus PDF from structured CRM and template data.
- Word/WPS editing happens outside CRM.
- Saving an externally edited next version requires both the updated DOCX and the PDF exported from that same edited document. This preserves source/PDF parity without relying on an unverified server-side Office converter.
- The new uploaded version inherits the prior frozen equipment and template-source snapshot. Regeneration from newly changed equipment or templates is a separate future operation, avoiding false provenance.

## Permissions

- Opportunity visibility continues to use the existing Opportunity access rules.
- Only the active assigned Quotation Engineer may create or update equipment, create V1, or save a later version.
- Technical Managers continue to author, review, publish, and retire standard templates.
- Administrators retain their existing template-library and Opportunity visibility boundaries; no ordinary-user role selector is added.

## Safety and compatibility

- Existing technical-solution tables, routes, document files, and approvals are not repurposed.
- Formal versions, version-item snapshots, stored files, and audit events reject update and delete operations at the database layer.
- File downloads return stored MIME type, exact byte length, and SHA-256 integrity metadata.
- No engineering value is invented by the system. Missing values remain visibly blank in generated material.
