# BESTCRM 新产品开发——框架结构（冻结）

状态：2026-09-26 用户确认顶层框架，并补充“方案确认后才能进入详细设计”的阶段门控原则。本文件只冻结业务边界、一级结构、对象关系和门控方向；不批准实现、提交或部署。字段、编号、具体状态机、评审人、门槛证据、权限矩阵、文件存储方案、页面细节及接口仍待逐项审核。

## 1. 定位与边界

“新产品开发”是独立于商机的研发与技术知识资产模块，不是商机的一个阶段，也不是产品分类中的一项。它覆盖既有产品升级、客户提出的新想法、商机带来的非标需求、内部研发，以及实施和售后反馈引发的技术课题。课题可以成功、部分成功、暂停或失败；研究过程和经整理的经验均保留。

模块以胜开尔的三个产业方向组织知识，且一个课题可同时涉及多个方向：

1. 工艺技术；
2. 关键设备；
3. 实施支持。

这三个方向是研发/知识分类维度，不替代 CRM 现有的产品类别或商机产品明细。

## 2. 一级功能结构

```text
新产品开发
├─ 课题总览
│  └─ 研发课题（统一身份；想法成熟后不另建重复课题）
│     ├─ 基础研究
│     ├─ 开发与验证
│     ├─ 协作与决策
│     ├─ 结论与版本
│     └─ 关联业务
└─ 技术资产库
   ├─ 已验证、可复用的技术成果
   └─ 经整理的经验、限制条件和失败教训
```

“基础研究”是每个课题的正式工作区，承载需求与技术调研、竞争对手分析、专利分析及其来源、原始实验数据等。研发资料不以商机附件作为唯一归属。技术资产库只汇集已审核的可复用成果和经整理的经验，不把未验证方案伪装为成熟技术。

## 3. 核心对象关系

```text
来源（客户想法 / 商机 / 产品升级 / 内部研发 / 实施反馈）
                         ↓
                  独立的研发课题
                         ↓
       研究资料 + 开发验证记录 + 协作决策历史
                         ↓
              有版本、有适用条件的结论
                    ↙             ↘
          技术资产库          经审核后被业务引用
                                  ↓
                   商机对客方案 / 产品升级 / 实施支持
```

一个研发课题可以关联多个商机；一个商机也可以关联多个研发课题。关联只建立可追溯引用，不要求复制整套研究文件，也不要求课题创建时已有商机。

课题的进展与结果是不同概念：进行到哪一步不等同于最后是否成功。失败或暂停不删除原始证据、讨论、试验和结论；但未验证的方案不得作为已验证技术成果供对客使用。

## 4. 与商机及其他系统的边界

- **研发课题**保存内部研究的原始资料、分析、试验、协作、决策与版本历史。
- **商机**保存已确认的对客最终方案及其交付版本，并可引用有权限且已审核的研发结论。竞品分析、专利分析和实验原始数据不因关联商机而自动出现在商机内。
- 已交付客户的方案是当时的固定版本；研发课题后续修改不能追改历史对客版本。
- **产品、项目执行及未来的工程系统**可以与课题或成果建立关联，但本模块不复制其权威记录，也不在此阶段规定 CAD/PDM/PLM 的文件职责或接口实现。
- 客户保密资料与可全公司复用的通用知识必须区分；关联商机不自动扩展研究资料访问权限。
- 用户已明确“Google Drive 升级”为误输入；Google Drive 迁移、购买或集成不属于本框架。

## 5. 开发流程的阶段门控原则

```text
创意与问题提出 → 多方讨论和轻量调研/试验 → 概念方案评审
                                              ├─ 确认方向 → 详细设计 → 验证与结论
                                              ├─ 修改方向 → 回到调研/概念方案
                                              └─ 暂停或终止 → 保留证据和经验
```

- 在概念方案确认之前，允许销售、工艺、设备、实施等相关人员参与创意讨论、比较备选技术路线，并做必要的低成本验证；不要求先完成整套详细图纸、计算和 BOM。
- **概念方案确认是正式详细设计的入口门槛。**必须先明确要解决的问题、拟采用的方向、主要假设和风险，并保存评审决定及当时的方案版本。具体必备证据、决策权限和客户参与条件留到流程细节阶段确定。
- 评审至少支持继续、调整后重审、暂停或终止。不得为了“完成流程”强迫错误方向进入详细设计。
- 探索阶段可以做必要的样机、计算或实验以排除关键风险，但这些工作必须标识为探索验证，不能冒充已批准的详细设计或对客定型方案。
- 若后续证据推翻了核心方向，应回到概念方案评审并形成新版本；原决定、试验数据和未采纳原因保留，不覆盖历史。

门控强度应与课题风险和投入相称，避免把小型探索变成重审批流程；本文件不固定表单数量、评审人数或时限。该方向借鉴了 [ISO/IAF 关于设计开发分阶段评审、相关职能参与及评审记录的指导](https://committee.iso.org/files/live/sites/tc176/files/documents/ISO%209001%20Auditing%20Practices%20Group%20docs/Auditing%20to%20ISO%209001%202015/APG-Design%26Development2015.pdf)，但不是对认证要求的额外声明。

## 6. 冻结的结构性验收原则

以“某商机涉及新产品”为例，应能先有或新建一个独立课题，在课题内持续保存调研、竞品、专利、实验和评审资料。商机仅关联该课题中经过审核、明确版本与适用条件的结论，并保存给客户的最终方案快照。即使商机结束，课题和研究资料仍独立存在；若课题后来失败，其证据和教训仍可按权限检索，但不会变成可直接复用的成熟方案。
