# BESTCRM 商机团队、客户与联系人访问控制设计

- 日期：2026-10-14
- 状态：客户/联系人主档、商机团队与主联系人权限边界已在本地实现并完成全量回归；生产发布由独立发布流程记录。多联系人关联界面仍按“后续由 opportunity_contacts 支持”的既定范围迭代。
- 范围：客户、联系人、商机、项目资料、邮件及附件的服务端访问控制
- 部署：本文件仅定义权限设计；发布授权与部署记录由独立发布流程管理。

## 1. 已确认的业务事实

SUNKAIER 的非标设备业务不是按固定销售部门长期协作。每个商机在创建/立项时，才由销售、技术及其他必要人员组成一个项目团队。因此：

1. 商机团队是项目资料访问的主边界，不是固定组织部门。
2. 客户协调人是客户主档和联系人主档的默认责任人。
3. 项目成员需要完成方案、报价、审批或交付时，可以查看该项目所需的客户与联系人信息，但不能因此浏览该客户的其他项目或全部联系人。
4. 管理员保留全局查看和管理权限。
5. 任何用户都不得仅凭“销售经理”“技术人员”等角色，获得全公司客户或联系人总库的默认可见性。

这替代当前“登录即可查看全部客户和联系人”的共享模式。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| 客户协调人 | customers.coordinator_user_id 所指的主责任人；旧字段 owner_user_id 仅作兼容别名。 |
| 商机团队 | 某一商机的有效成员：销售、被分配的技术/报价/审批人员，以及 opportunity_members 中处于 active 状态的成员。 |
| 客户主档 | 客户的完整主数据、全部联系人、全部历史项目和内部备注。 |
| 项目上下文客户卡 | 在一项已获授权商机内展示的必要客户字段，例如名称、地区、地址及该项目的商务联系信息。 |
| 项目联系人 | 明确关联到该商机的联系人；现阶段至少包括 primary_contact_id，后续由 opportunity_contacts 支持多联系人。 |

## 3. 权限总原则

### 3.1 客户主档与联系人主档

客户协调人只能在客户/联系人总库中看到自己协调的客户及其联系人。管理员可以查看和管理全部主档。其他人不出现在客户、联系人列表和搜索结果中，也不能通过猜测 URL、API 参数、导出、自动补全或历史链接取得主档。

联系人继承所属客户的主档权限；联系人没有独立的“全公司公开”状态。

### 3.2 商机团队

商机可见人包括：

1. 管理员；
2. 该商机所关联客户的客户协调人；
3. 商机的销售、销售经理、报价工程师、技术经理、商务经理等已指定流程责任人；
4. opportunity_members 中仍有效的项目成员；
5. 当前待办或审批步骤明确指派的人员，仅在完成其被授予的项目职责所需范围内。

被移出商机团队后，成员立即失去该商机、相关邮件、附件、项目联系人和项目资料的访问权；其过往操作和团队成员变更记录仍保留在审计历史中。

### 3.3 项目团队所见的数据最小化

项目成员不获得客户主档浏览权。他们只能在自己可查看的商机中看到：

- 项目所需的客户卡片；
- 已被关联到该商机的联系人；
- 该商机的邮件、附件、技术资料、报价资料和流程记录，且仍受各资料自身的角色/状态限制。

项目成员不能从项目上下文跳转至客户的全部联系人、其他项目、客户内部备注或其他项目团队的文件。

## 4. 确认后的权限矩阵

| 操作/数据 | 客户协调人 | 有效商机团队成员 | 被指派审批人 | 管理员 |
| --- | --- | --- | --- | --- |
| 客户总库列表/搜索 | 仅自己协调的客户 | 否 | 否 | 全部 |
| 联系人总库列表/搜索 | 仅自己协调客户的联系人 | 否 | 否 | 全部 |
| 客户主档（完整） | 自己协调的客户 | 否 | 否 | 全部 |
| 联系人主档（完整） | 自己协调客户的联系人 | 否 | 否 | 全部 |
| 商机详情 | 自己协调客户下的商机 | 已加入的商机 | 被指派的商机 | 全部 |
| 商机中的客户卡/项目联系人 | 是 | 仅本商机范围 | 仅本商机范围 | 是 |
| 编辑客户/联系人主档 | 是 | 否 | 否 | 是 |
| 添加/移除商机团队成员 | 提出或参与流程；以现有职责规则为准 | 否，除非另行授权 | 否 | 是 |
| 管理商机团队 | 由销售经理/管理员按流程管理并留审计 | 否 | 否 | 是 |

“销售经理”角色本身不产生全局客户库权限。销售经理在一项商机中被指定为 sales_manager_id、待办审批人或有效商机成员时，才取得该项商机的项目范围访问权。

## 5. 同一客户的多个非标项目

一个客户可以同时有多项设备项目，且每项项目拥有不同成员组合。

- 客户协调人可查看自己客户下的全部项目与联系人。
- A 项目团队只能查看 A 项目及其明确关联的联系人。
- A 项目团队不因客户相同而自动查看 B 项目、B 项目的联系人、邮件、报价或附件。
- 如需跨项目协作，必须把人员明确加入对应商机团队；不以角色或同一客户为理由隐式开放。

## 6. 客户与联系人创建、重复和转交

### 6.1 新建

新建客户默认将创建者设为客户协调人。新建联系人必须由该客户协调人或管理员执行；项目成员不能直接修改客户主档或联系人主档。

### 6.2 重复检测

客户名称和联系人身份的重复检测仍在服务端全局执行，以防形成重复档案。但无权查看既有主档的用户只能得到通用结果，例如“该记录已存在，请申请协调或加入项目协作”，不能得到既有客户负责人、联系人数量、其他项目或邮件等信息。管理员在有正当业务需要时可以处理转交、合并或授权。

### 6.3 协调人转交

转交客户协调人必须记录发起人、原协调人、新协调人、原因和时间。转交后：

- 新协调人取得客户主档、联系人和该客户项目的责任范围；
- 原协调人默认失去主档和非其项目的访问权；
- 如原协调人仍需参与某一项目，应保留或新增该项目的商机成员关系，而不是保留整个客户库权限。

## 7. 服务端强制规则

前端隐藏按钮不是权限控制。以下所有入口必须调用同一套服务端判定：

1. 客户/联系人列表、搜索、筛选、分页和自动补全；
2. 客户/联系人详情、编辑、新建、归档、恢复、合并和导出；
3. 商机详情、商机联系人、客户卡、团队成员和相关工作台任务；
4. 邮件线程、附件预览/下载、技术资料、报价、合同和 API；
5. 直接 URL、表单 POST、JSON API、批量操作和后台任务。

对于无权查看的客户、联系人或商机，应返回“未找到”语义，不应泄露记录是否存在、负责人、联系人数量或项目名称。拒绝尝试和成员变更应写入审计记录。

## 8. 数据与实现边界

已有的 opportunity_members、成员权限级别、任务范围和成员事件记录可作为商机团队的基础，不需要把每个项目复制成固定组织团队。

需要补齐的实现能力包括：

1. 客户和联系人查询接收服务端可见范围，不再默认全库查询；
2. 以客户协调人判断客户/联系人主档权限；
3. 以既有商机成员和流程责任人判断商机权限；
4. 引入或完成 opportunity_contacts，使一个商机可显式关联多个联系人；
5. 在商机页面提供受限的客户卡和项目联系人视图，而不是跳转到完整客户主档；
6. 使邮件、附件、导出和选择器复用相同判定；
7. 保留管理员处理转交、合并和异常授权的受审计入口。

不允许复制客户或联系人来绕过权限；客户和联系人仍是唯一主数据，商机保存关系和历史快照。

## 9. 数据迁移原则

本设计不删除或重写现有业务资料。实施前应：

1. 列出没有有效客户协调人的客户，先由管理员补齐；
2. 以现有 coordinator_user_id 为客户主档的初始责任边界；
3. 保留现有商机各流程责任人，并回填需要的 opportunity_members 关系；
4. 对每个存量商机确认 primary_contact_id，后续逐步补充多联系人关联；
5. 在隔离环境验证“旧共享读取”与“新授权读取”的预期差异；
6. 在上线前完成数据库备份、回滚说明、权限回归测试和业务抽样验收。

## 10. 验收标准

上线前至少证明以下场景：

1. 销售 A 无法在列表、搜索、URL、API 或导出中发现销售 B 协调的客户和联系人。
2. 销售 A 能完整管理自己协调客户及其联系人。
3. 被加入 A 项目的技术人员能查看 A 项目的必要客户卡和项目联系人，但不能查看该客户其他联系人或 B 项目。
4. 同一客户的两个项目团队不能互相查看邮件、附件、报价和技术文件。
5. 商机成员被移除后，旧链接、文件 URL、API 和工作台入口均失效。
6. 已指派审批人可在职责范围内打开项目和所需资料，但不能浏览客户总库。
7. 管理员可处理转交、合并和异常恢复，且每次操作留有审计记录。
8. 无权限创建重复客户时，系统不泄露既有记录的敏感信息。

## 11. 实施门槛

任何数据库迁移、权限切换、生产部署或 DNS/服务器变更，均须在完成本设计评审后取得明确批准，并由独立发布流程留存记录。
