# BESTCRM 用户使用手册

版本：V1.0  
适用对象：销售、销售经理、报价工程师、技术经理、商务经理、法务审批人、系统管理员

## 1. 系统入口

公网访问地址：

```text
http://175.27.225.156/login
```

用户使用系统管理员分配的账号和密码登录。首次登录后，如管理员要求，请及时修改登录密码。

登录页支持语言选择：

- English
- 中文

语言在登录前选择，登录后系统按所选语言显示。

## 2. 左侧导航

登录后进入工作台，左侧为固定导航栏：

- 工作台：查看本人待办、流程消息、商机状态统计。
- 商机：查看商机清单，创建新商机，进入商机详情。
- 客户：维护客户资料，查看客户联系人。
- 联系人：维护联系人资料。
- 系统：仅管理员可见，用于维护用户、角色、审批人配置。
- 退出登录：安全退出系统。

## 3. 角色说明

系统内置角色如下：

| 角色 | 主要职责 |
| --- | --- |
| Sales / 销售 | 创建商机、提交立项、补充客户需求、跟进中标/未中标、提交合同审批 |
| Sales Manager / 销售经理 | 审批商机立项，批准后指派报价工程师 |
| Quotation Engineer / 报价工程师 | 编制技术方案、上传技术附件、提交商务报价 |
| Technical Manager / 技术经理 | 审批或驳回技术方案 |
| Commercial Manager / 商务经理 | 审批或驳回商务报价 |
| Legal Reviewer / 法务审批人 | 审批或驳回合同 |
| Finance Reviewer / 财务审批人 | 预留角色，用于后续合同或财务审批扩展 |
| General Manager / 总经理 | 预留角色，用于后续最终审批扩展 |
| Administrator / 系统管理员 | 维护用户、角色、审批人配置，管理系统基础资料 |

一个用户可以拥有多个角色。用户能看到和操作的内容取决于其角色及商机中的负责人配置。

## 4. 工作台

工作台用于处理当天最重要的事项。

### 4.1 我的待办

显示当前登录用户需要处理的任务。例如：

- 提交商机立项
- 审批商机立项
- 编制技术方案
- 审批技术方案
- 编制商务报价
- 审批商务报价
- 提交合同审批
- 审批合同

点击待办中的商机，可进入商机详情页处理。

### 4.2 最近流程消息

显示最近发生的流程动作，例如提交、审批、驳回、需求补充等。

### 4.3 工作流状态统计

显示当前系统内商机所处状态的数量，用于快速判断整体业务进度。

## 5. 客户管理

进入“客户”页面可查看客户清单。

### 5.1 新建客户

点击“新建客户”后填写：

- 客户名称
- 企业网站
- 行业
- 母公司
- 企业性质
- 国家
- 地区
- 地址
- 企业亮点
- 客户概况

行业为下拉选择，当前包括：

- 石油化工
- 精细化工
- 湿法冶金
- 环保
- 食品
- 医化
- 其他

企业性质为下拉选择，例如：

- 国营
- 私企
- 股份上市公司

国家下拉包含 195 个国家，并保留“Other”选项；中国位于首项，便于国内客户快速选择。地区下拉包含中国全部 34 个省级行政区，并保留“Overseas”和“Other”选项。

企业网站可填写完整网址或域名。若只填写域名，系统会自动补充 `https://`，并在客户详情页提供可点击链接。

### 5.2 客户详情

客户详情页显示客户基本信息和该客户下的联系人清单。

管理员可以删除客户。删除前系统会二次确认。若客户已关联商机，系统会阻止删除。

### 5.3 重复客户判断和处理

系统在新建客户、编辑客户名称，以及在新建商机页面快捷新增客户时检查重复客户。

- 判断标准：客户名称去除首尾空格后，不区分英文字母大小写；规范化后的名称完全相同即判为重复。
- 编辑现有客户时，系统会排除当前客户自身，只检查其他客户。
- 简称、相似名称、相同企业网站或同一集团不会自动判为重复，以避免误判分公司、子公司或不同法人主体。
- 发现重复后，系统阻止本次保存并保留已填写内容，同时显示已有客户名称、负责人和联系人数量。
- 操作人员应先与现有负责人协调，确认是在已有客户下继续跟进，还是使用能够区分主体的完整工商名称；系统不会自动合并、覆盖或删除客户资料。

## 6. 联系人管理

进入“联系人”页面可查看联系人清单。

### 6.1 新建联系人

联系人一般归属于某个客户。主要信息包括：

- 姓名
- 所属客户
- 职务
- 电话
- 邮箱
- 教育背景
- 工作经历
- 突出成就

### 6.2 联系人详情

联系人详情页以表格形式展示字段和值。

管理员可以删除联系人。删除前系统会二次确认。若联系人已关联商机，系统会阻止删除。

## 7. 商机管理

商机是本系统的业务主线。所有报价、审批、合同动作都围绕商机展开。

进入“商机”页面可查看商机清单。可组合选择商机范围、客户、主要联系人和销售负责人，并用关键词查询商机编号、商机名称、客户、负责人或主要联系人。点击清单任意单元格可进入商机详情。

商机清单主要字段：

- 商机编号
- 商机名称
- 客户
- Owner / 商机负责人
- 联系人
- 状态
- 预估金额

商机编号为 6 位数字，从 `800000` 起自动递增。

## 8. 新建商机

销售点击“新建商机”，填写：

- 客户
- 联系人
- 商机名称
- 客户需求
- 预估金额
- 项目类型
- 交付周期
- 预计投标日期

项目类型为下拉选择：

- 新增
- 扩建
- 改造
- 维修

交付周期表示预计从订单或合同生效到交付完成所需的周期，例如：

- 60 天
- 90 天
- 4 个月
- 2026 年 10 月前交付

若系统中没有客户，可在新建商机页面内新增客户。若没有联系人，可跳转新增联系人页面后再继续新建商机。

保存后，商机处于草稿状态。

## 9. 商机详情页

商机详情页分为主要区域：

- 基本信息
- 责任信息
- 需求资料
- 技术方案
- 商务报价
- 商务合同
- 时间线

### 9.1 基本信息

显示商机编号、客户、联系人、状态、预估金额、项目类型、交付周期、预计投标日期等。

右上角常用按钮：

- 返回清单
- 编辑
- 删除

删除商机仅管理员可操作，并会二次确认。

### 9.2 责任信息

责任信息包括：

- Owner：商机主负责人，一个商机只有一个 Owner。
- Team Members：协同负责人，可添加多个。
- Owner Transfer History：Owner 转移历史。

管理员或 Sales Manager 可以转移商机 Owner，并保留转移历史。

## 10. 需求资料

需求资料用于保存客户最初需求和后续需求补充。

内容按时间轴保存：

- 时间 - 文字内容
- 时间 - 文件名 - Preview / Download / Delete

销售可以在需求资料栏：

- 输入文字需求并保存
- 上传需求附件
- 提交立项给 Sales Manager

### 10.1 删除规则

商机提交立项前，需求附件可以删除。

商机提交立项后，需求资料作为业务记录锁定，只能预览和下载，不能删除。

### 10.2 需求补充

商机立项后，如客户提出新的需求，销售可在需求资料栏新增补充内容。

新增需求补充后，系统会把流程重新引导到技术方案处理，由报价工程师重新提交技术方案，技术经理再次审批。

## 11. 商机流程

### 11.1 草稿

销售创建商机后，商机处于草稿状态。

销售确认客户需求资料完整后，点击“提交给销售经理”。

### 11.2 立项审批

Sales Manager 收到待办后，进入商机详情审批。

审批结果：

- 批准：指派 Quotation Engineer，流程进入技术方案编制。
- 驳回：退回销售修改，销售可重新提交。

销售在审批完成前可以撤回提交。

### 11.3 技术方案

Quotation Engineer 在技术方案栏处理。

技术方案可以是三种情况：

- 只有文字描述
- 只有上传的技术附件
- 文字描述和技术附件都有

提交技术经理审批前，必须至少有技术方案文字或技术附件之一。

提交后形成版本记录，技术经理审批。

审批结果：

- 批准：流程进入商务报价编制。
- 驳回：退回报价工程师修改。

若技术方案被驳回，报价工程师必须上传新材料或输入新的技术方案文字后，才能再次提交。

### 11.4 商务报价

报价工程师在商务报价栏上传报价附件，然后提交给 Commercial Manager 审批。

商务报价以附件为准，不再单独填写报价明细表。

提交前必须有商务报价附件。

审批结果：

- 批准：流程进入客户商务谈判。
- 驳回：退回报价工程师修改。

若商务报价被驳回，报价工程师必须上传新版报价附件后，才能再次提交。

商务报价批准后，已提交版本不能删除。

### 11.5 客户结果

商务报价批准后，销售跟进客户结果。

两种结果：

- 未中标：填写未中标原因，流程归档结束。
- 中标：填写中标说明和成交金额，进入合同处理。

### 11.6 商务合同

销售在商务合同栏上传合同文件，并提交合同审批。

提交合同审批前必须有合同附件。

审批结果：

- 批准：合同归档，商机闭环。
- 驳回：退回销售修改合同。

合同被驳回后，必须上传驳回时间之后的新合同附件，才能再次提交审批。

合同提交审批后，已提交版本不能删除。

## 12. 文件操作

系统支持以下文件操作：

- Upload：上传文件
- Preview：预览文件
- Download：下载文件
- Delete：删除文件

注意：

- 删除前系统会二次确认。
- 已进入审批或已审批通过的材料，通常不能删除。
- 被驳回后再次提交，必须提供新版材料。
- 文件名建议使用清晰命名，例如：`客户简称_技术方案_V1.pdf`、`客户简称_报价单_V2.xlsx`。

## 14. 系统管理

系统菜单仅管理员可见。

### 14.1 用户

管理员可以：

- 新增用户
- 编辑用户
- 设置或修改登录密码
- 分配角色
- 删除用户

删除用户前系统会二次确认。

正式使用中，不建议删除已参与业务流程的用户。若人员离职，优先停用或更换负责人。

### 14.2 角色

管理员可以维护角色。

系统内置角色与流程强相关，正式使用中不建议随意删除或改动角色编码。

### 14.3 审批人配置

管理员维护各流程节点的审批人：

- opportunity_initiation：商机立项审批人
- technical_solution：技术方案审批人
- commercial_quote：商务报价审批人
- contract_approval：合同审批人

每个配置必须指向一个有效且启用的用户。

如果审批人配置错误，流程提交时会提示审批人未配置或无法生成待办。

## 15. 日常使用建议

### 15.1 销售

- 客户需求未明确前，不要提交立项。
- 需求资料尽量文字和附件都保留。
- 客户有新要求时，及时在需求资料栏补充，不要只在线下沟通。
- 中标或未中标后及时归档，避免商机长期停留在谈判状态。

### 15.2 报价工程师

- 技术方案和商务报价都应按版本上传。
- 被驳回后，必须上传或填写修改后的新材料。
- 文件命名要体现客户、内容、版本。

### 15.3 审批人

- 审批前查看对应材料和时间线。
- 驳回时应填写明确原因，便于下一步修改。
- 不建议在线下审批后不在系统中操作。

### 15.4 管理员

- 新增员工后，确认角色和审批人配置。
- 定期检查用户是否仍有效。
- 不要在生产环境随意运行初始化脚本。
- 定期备份数据库和上传文件。

## 16. 生产环境注意事项

当前系统已部署在云服务器，公网访问使用 IP。

正式使用后：

- 不要直接删除数据库。
- 不要随意运行 `npm run db:seed`。
- 修改系统前先做备份。
- 重要修改先在本地验证，再发布到云服务器。
- 生产管理员密码应尽快改为正式密码。

## 17. 常见问题

### 17.1 登录失败怎么办？

先确认访问地址是否正确：

```text
http://175.27.225.156/login
```

不要使用：

```text
http://127.0.0.1:3000/login
```

`127.0.0.1` 是本机地址，不是云服务器地址。

### 17.2 看不到系统菜单？

系统菜单仅管理员可见。请联系管理员检查账号是否有 Administrator 角色。

### 17.3 提交审批按钮不可用？

通常原因：

- 当前状态不允许提交。
- 当前用户不是该节点处理人。
- 必填材料未上传。
- 被驳回后没有上传新版材料。
- 审批人配置缺失或无效。

### 17.4 文件不能删除？

提交审批后，材料会成为流程记录，通常不能删除。若需要修正，应上传新版材料并重新提交。

### 17.5 审批人收不到待办？

请管理员检查“系统 > 审批人配置”，确认对应节点已配置有效用户。
